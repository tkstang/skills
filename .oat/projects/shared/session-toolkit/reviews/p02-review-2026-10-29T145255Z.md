### High

- **H1: Unrelated Codex sessions make exact reads unavailable** (`packages/session-toolkit/src/discovery.ts:209`)

  Issue: Every successfully decoded session whose ID differs from the requested pin adds `codex:identity-mismatch`. Codex intentionally scans metadata rather than prefiltering filenames, so any normal store with a second, distinct session gets incomplete coverage. `resolveSession` then rejects the unique correct candidate. A controlled one-session store reads successfully; adding one valid unrelated rollout makes both `readTranscript` and `readEvidence` reject with `E_UNAVAILABLE`. Exact Codex export uses the same resolver. The existing native-carrier regression covers duplicate carriers but omits the distinct-session case.

  Fix: Treat a valid, unrelated native session as an ordinary filtered nonmatch. Preserve refusal for an actual conflicting carrier claiming the selected identity, incomplete scans and duplicate matches. Add one public-boundary regression with two distinct valid Codex sessions; retain the nonstandard/case-varied carrier and duplicate controls.

  Requirement: p02 exact qualified session read/evidence/export; package contract says filters intersect and ambiguity refers to matching carriers.

- **H2: The reader normalizes every growing record prefix** (`packages/session-toolkit/src/reader.ts:262`)

  Issue: Even when no message limit is requested, each decoded row copies all earlier rows, normalizes the entire prefix and remaps every rendered entry. This makes ordinary parsing quadratic. On synthetic 46-byte Claude records, 1,000 records took 745 ms, 5,000 took 23,179 ms and 10,000 took 92,502 ms, while one normalization of those same 10,000 records took 13 ms. The slowest input is only 460,000 bytes, well below the default 4,000,000-byte page. CLI parse/read/export and bounded evidence paths share this reader, so routine transcript sizes can stall for minutes.

  Fix: Accumulate the bounded source page and normalize once when message counting is unnecessary. Preserve whole-record message-limit behavior with proportionate incremental/counting work rather than repeatedly projecting every prefix. Verify a representative multi-thousand-record public parse and the existing message-limit/Cursor-coordinate controls; no separate benchmark framework is needed.

  Requirement: p02 bounded public reads/parse and usable stateless export; the byte bound must not hide this substantial CPU amplification.

- **H3: Claude exact identity rejects the current project slug for ordinary cwd punctuation** (`packages/session-toolkit/src/identity.ts:224`)

  Issue: Claude cwd validation replaces only slashes/dots, leaving underscores and spaces intact. The same extracted identity module documents and implements the current all-nonalphanumeric-to-hyphen layout in `locateTranscriptById` at lines 284–292. A controlled cwd named `repo_with_space`, its exact harness ID and a single correctly encoded direct transcript produce `matchCount: 1` but `status: invalid` / `W_CWD_MISMATCH`. Thus `self-identify` rejects a valid provider layout for common repository names. Current tests generate slugs with the same incomplete replacement as the implementation.

  Fix: Use the established current Claude slug encoding consistently in exact identity and shared cwd encoding, retaining the already selected supported variants. Add a fixture whose expected slug independently encodes an underscore or space and preserve the wrong-project/duplicate refusal controls.

  Requirement: p02 merges ORC exact identity with provider knowledge and supports controlled Claude exact/ambiguous/unavailable cases.

Unpinned discovery consequently lists `cursor:<id>` for `agent-transcripts/<id>/transcript.jsonl`. The controlled generic carrier was listed successfully and then refused with `E_UNAVAILABLE`.

  Fix: Apply Cursor identity extraction before rejecting generic carriers, or constrain the prefilter using the actual supported layout. Cover the public list-to-read round trip for one generic filename, preserving duplicate-carrier refusal.

- **M2: Evidence compares canonical and raw cwd strings as different identities** (`packages/session-toolkit/src/evidence.ts:343`)

If metadata names a symlink alias for the same directory, `identifyCurrentTranscript` correctly returns authoritative after canonical revalidation, but `readEvidence` rejects with `EVIDENCE_SOURCE_IDENTITY_MISMATCH`. The canonical-path accepted control and alias failing control have identical native IDs and underlying source cwd.

  Fix: Canonicalize the captured cwd before comparing it with the selected canonical cwd, while preserving raw metadata evidence and genuine different-cwd refusal. Keep cutoff identity consistently bound to the canonical directory; add the public evidence alias case alongside a different-directory control.

  Requirement: p02 exact evidence/source revalidation and the existing canonical cwd identity semantics (also explicitly exercised by the identity test suite).
