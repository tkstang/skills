### Important

- **Exact identity discovery hides cross-slug duplicates and downgrades symlink-equivalent cwd pins** (`src/transcript/session-observer/lib/locate.ts:581`)
  - Issue: `discoverCursor()` returns as soon as any direct transcript exists, so `resolveCursorIdentity()`'s duplicate scan at lines 722-734 never sees the same session ID under another Cursor project slug. A generated-runtime reproduction with one direct and one fallback `same/transcript.jsonl` returned only the direct path and resolved the explicit pin as `strength: exact` with no reasons. Discovery also derives the direct slug from the raw requested cwd before the resolver canonicalizes it. With a symlink cwd whose transcript is stored under the physical cwd slug, discovery returns only fallback evidence and the exact explicit pin is downgraded to `diagnostic`/`WEAK_CWD_EVIDENCE`. The existing symlink test sidesteps this by discovering with the physical cwd and manually replacing `recordedCwd`. These behaviors violate FR1's duplicate fail-visible rule and the design requirement to canonicalize cwd before deriving path variants.
  - Fix: Canonicalize the requested cwd before computing direct Cursor store variants, while preserving the supplied spelling for display. Give exact identity resolution an all-store same-session collision check that is not suppressed by direct-hit ranking, canonicalize every candidate path, and reject distinct canonical paths. Add real discovery tests for alias-cwd lookup and a direct-plus-other-slug duplicate.
  - Requirement: FR1, NFR1

- **A real process crash can strand inner state locks and make migration retry permanently fail** (`src/transcript/session-observer/lib/state.ts:111`)
  - Issue: The outer `cursor-state-transition.lock` records a PID and removes dead owners, but both inner `state.json.lock` and `cursor-state.json.lock` are empty exclusive-create files with no stale-owner recovery (`state.ts:111-125`; `cursor-state.ts:515-529`). The migration failure tests throw exceptions, allowing `finally` to release every lock, so they do not model process death. In a generated-runtime subprocess reproduction, SIGKILL at the declared `backup-written` boundary left `state.json.lock`; the next migration removed the dead transition lock but timed out after all 100 inner-lock retries with `state.mjs: could not acquire lock`. The durable marker and backup remained present but unusable without manual lock deletion, contradicting p02-t03's crash-retry contract and FR6.
  - Fix: Use one recoverable owner-aware protocol for every state lock, including safe handling of a crash between lock creation and owner metadata persistence. Add subprocess SIGKILL tests at each migration/compatibility boundary and during a v2 mutation; retries must reclaim only demonstrably dead owners and complete without manual deletion.
  - Requirement: FR4, FR6, NFR3

- **Delivery CAS can commit a different exact transcript identity or a changed same-boundary prefix** (`src/transcript/session-observer/lib/cursor-state.ts:198`)
  - Issue: `isForwardDeliveryCheckpoint()` checks frame and prefix-length monotonicity plus device/inode, but accepts a different `prefixSha256` when `intended.prefixBytes === expected.prefixBytes`. `commitCursorDelivery()` then compares checkpoints but never requires `nextState.canonicalCwd` or `nextState.transcriptPath` to equal the reserved current entry before replacing it at line 918; `setCursorSession()` has the same identity-replacement opening while a matching reservation remains active. Generated-runtime reproductions reserved a checkpoint with the same 128-byte boundary but a different hash, and separately committed frame 3 to frame 5 while changing `/cwd-a`/`/store/a.jsonl` to `/cwd-b`/`/store/b.jsonl`; both operations succeeded and the substituted identity was durable. This permits a caller bug or validation/commit race to hide prefix mutation or carry a cursor across an unproven path boundary.
  - Fix: When the intended prefix boundary is unchanged, require the hash to be unchanged. Bind each reservation to canonical cwd and transcript path (or the complete exact identity) and require reserve, commit, and any pending-preserving set operation to match the current entry before mutation. Add same-boundary hash, canonical-path, canonical-cwd, wrong-index-base, backward-frame/prefix, and device/inode mismatch tests at both reserve and commit.
  - Requirement: FR1, FR4, FR6, NFR5

### Medium

- **The documented session-scoped recovery command cannot reset corrupt/schema-invalid v2 state** (`src/transcript/session-observer/lib/cursor-state.ts:989`)
  - Issue: `resetCursorSessionState()` uses the ordinary mutator, so corrupt/schema-invalid bytes cause `CURSOR_STATE_RECOVERY_REQUIRED`; `state reset --session cursor:<id>` routes directly through that function at `state.ts:945-956`. The new test matrix explicitly expects session reset to reject and demonstrates recovery only with global `resetAllCursorState()`. The design and CLI contract name session-scoped reset as the explicit recovery path. Because a corrupt global file cannot safely identify or preserve other sessions, the shipped behavior may be defensible, but the recovery contract is currently misleading and leaves the structured error without its documented command.
  - Fix: Define an explicit corrupt-store recovery operation and diagnostic. Either require a clearly confirmed whole-Cursor-store quarantine/reset and update the design/CLI guidance, or implement a safe session recovery protocol that does not pretend it can preserve unparseable sibling state. Add CLI-level corrupt/schema recovery tests.
