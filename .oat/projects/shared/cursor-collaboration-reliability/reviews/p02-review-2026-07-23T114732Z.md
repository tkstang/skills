### Important

- **A crash before contender-token publication permanently wedges all three state-lock queues** (`src/transcript/session-observer/lib/state.ts:164`)
  - Issue: `createLockContender()` publishes the queue ticket with `open(ownerPath, 'wx')` before writing and syncing its owner token. A SIGKILL, write failure, or datasync failure in that interval leaves an empty or partial `.lock.owners/*.owner` file. `contenderOwnsTurn()` treats an invalid owner as fail-closed and returns `false`, but no path can remove or repair that earliest ticket. Every later operation exhausts all 100 retries. The same implementation protects `state.json.lock` and `cursor-state-transition.lock`; the mirrored implementation in `cursor-state.ts:581-645` protects `cursor-state.json.lock`. A generated-runtime reproduction with an empty first `state.json.lock.owners` ticket failed after 5.2 seconds with `state.mjs: could not acquire lock after 100 retries`; the lock reconnaissance reproduced the same failure for the Cursor store. Existing SIGKILL tests begin only after the application acquires the lock, so they miss this publication boundary.
  - Fix: Publish contender tokens atomically—for example, write/fsync a uniquely named private token and hard-link or rename it into the numbered queue position only after it is valid—or add exact-generation cleanup for never-valid queue entries without weakening fail-closed handling of legacy live main locks. Add subprocess SIGKILL/error-injection tests at open, write, and datasync boundaries for the legacy-state, Cursor-state, and transition lock queues; every retry must recover without manual file deletion.
  - Requirement: FR4, FR6, NFR3

- **An ancestor-component symlink lets a raw cwd alias become exact identity evidence** (`src/transcript/session-observer/lib/locate.ts:788`)
  - Issue: Raw variants are labeled `raw-cwd-alias` only when `lstat(targetCwd).isSymbolicLink()` is true. For a path such as `/alias-parent/project`, where `alias-parent` is a symlink but the leaf `project` is a normal directory, canonical and raw encodings differ while the leaf lstat is false. The raw store variant is labeled `direct-parent-dir`, mapped to `direct-project-root`, and can satisfy exact cwd plus explicit-session evidence. A generated-runtime reproduction returned `candidateEvidence: direct-parent-dir`, `strength: exact`, and no reasons for an alias-only transcript. This violates the explicit Phase 2 requirement that raw symlink aliases distinct from canonical identity remain diagnostic-only and can let a non-canonical store variant own state.
  - Fix: Detect a raw alias by comparing the normalized supplied cwd spelling with the resolved canonical cwd, not by inspecting only the final path component. Mark every raw-derived encoding that differs from the canonical encoding as diagnostic-only, and add leaf- and ancestor-symlink cases plus canonical/raw duplicate cases to the identity matrix.
  - Requirement: FR1, NFR1

### Medium

- **Shipped state-recovery guidance contradicts the Cursor v2 operator contract** (`skills/session-observer/SKILL.md:64`)
  - Issue: The command table says runtime and session reset merely zero `lastRecordIndex`, while Cursor v2 reset deletes session state and corrupt/schema recovery requires destructive whole-store replacement. The corruption section at `skills/session-observer/SKILL.md:382` still says corrupt state is automatically replaced with an empty store, and the documented fallback is recursive deletion. Current code instead preserves corrupt bytes, emits `CURSOR_STATE_RECOVERY_REQUIRED`, directs the operator to `state reset --runtime cursor`, and truthfully reports that sibling Cursor sessions cannot be preserved. The CLI behavior and structured diagnostics are correct, but the shipped user-facing recovery documentation is not.
  - Fix: Add a Cursor-specific state-v2 recovery section that distinguishes session deletion/replay from non-Cursor offset zeroing, documents the fail-closed corrupt/schema outcome and destructive whole-runtime reset command, and removes the claim that Cursor corruption automatically starts fresh. Keep the generic recursive-delete escape hatch clearly secondary and destructive.
