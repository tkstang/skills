### Important

- **Stale-lock recovery can steal a live lock and break mutual exclusion** (`src/transcript/session-observer/lib/state.ts:149`)
  - Issue: Both owner-aware lock implementations read an owner, stat the path, decide that observed generation is stale, and then blindly `unlink(path)` (`state.ts:149-161`; `cursor-state.ts:571-583`). If two successors inspect the same dead owner, successor A can unlink it and publish a live replacement before successor B executes its already-authorized unlink; B then deletes A's live lock and can enter the same critical section. The invalid-owner grace is independently unsafe across an upgrade: the prior runtime used an empty exclusive lock, so after one second the new runtime deletes that still-live old lock without evidence that its owner died. A generated-runtime probe held a pre-fix empty `state.json.lock` in a live subprocess; the round-3 writer reclaimed it and committed in 28 ms while the holder remained alive. These openings undermine cross-store rollback, migration retry, and every otherwise-correct state CAS.
  - Fix: Make stale reclamation ownership-safe for the exact observed lock generation, and fail closed for legacy/invalid locks unless an explicit recovery protocol proves ownership is dead. Add deterministic tests with two coordinated reclaimers where one replaces the lock between the other's inspection and deletion, plus a live pre-upgrade empty-lock holder for `state.json.lock`, `cursor-state.json.lock`, and the transition lock.
  - Requirement: FR4, FR6, NFR3

- **The unrestricted session setter bypasses continuity and delivery CAS** (`src/transcript/session-observer/lib/cursor-state.ts:820`)
  - Issue: `setCursorSession()` protects an active pending delivery, but when `pendingDelivery` is null it unconditionally replaces an existing entry at line 835. Against the generated runtime, an existing frame-5 checkpoint for `/cwd-a` and `/a.jsonl` was durably replaced by a frame-2 checkpoint for `/cwd-b` and `/b.jsonl`. This silently performs the exact rewind and cross-identity cursor inheritance that `validateCursorContinuity()`, explicit reset, and expected-checkpoint CAS are designed to block. No production caller uses the helper yet, but Phase 2 exports it as the state initialization/update primitive that Phase 3 is intended to consume.
  - Fix: Separate create-if-absent initialization from updates. Reject replacement of an existing entry unless exact identity is unchanged and a supplied expected checkpoint proves a monotonic transition; route cursor advancement through the reservation/commit CAS and identity changes through explicit reset/replay. Add no-pending tests for frame rewind, cwd/path substitution, device/inode change, and prefix replacement.
  - Requirement: FR1, FR4, FR6

### Medium

- **Whole-store corruption recovery is not connected to the documented state command** (`src/transcript/session-observer/lib/state.ts:948`)
  - Issue: `recoverCursorStateStore()` correctly requires explicit whole-store confirmation and reports that sibling sessions cannot be preserved (`cursor-state.ts:1098-1137`), but `state.ts` neither imports nor exposes it. The documented `state reset --session cursor:<id>` still calls `resetCursorSessionState()` and fails with `CURSOR_STATE_RECOVERY_REQUIRED` on corrupt/schema-invalid bytes. A CLI probe confirmed the session command exited 1 while preserving the corrupt bytes; only `state reset --runtime cursor` happened to clear the whole store, and the diagnostic does not direct the operator to that reachable command. The new tests call only the low-level recovery export.
  - Fix: Define one operator-facing contract now: either wire an explicitly confirmed whole-Cursor-store recovery through composed state/CLI and test corrupt/schema cases at that boundary, or document `state reset --runtime cursor` as destructive whole-store recovery and align the error metadata and design. Do not continue promising session-preserving recovery for an unparseable shared store.

### Minor

- **Raw symlink cwd spellings are accepted as exact beyond the canonical-only design** (`src/transcript/session-observer/lib/locate.ts:550`)
  - Issue: Discovery derives direct variants from both canonical cwd and raw supplied cwd, then labels either `direct-parent-dir`. An alias-only transcript therefore resolves to the physical canonical cwd with `strength: exact`; the generated-runtime probe confirmed this. The implementation remains defensible because persisted cwd/path are canonical and same-session cross-path duplicates fail closed, but the design says to canonicalize before deriving variants and retain the supplied spelling only for display.
  - Suggestion: Either document alias-encoded Cursor store directories as supported exact evidence when paired with an explicit session and canonical contained transcript path, or keep raw variants diagnostic-only. Add alias-only coverage so this remains a deliberate contract.
