### Important

- **I1 — Delivery-uncertain replay no longer reproduces the reserved entry set after lifecycle advances** (`src/transcript/session-observer/lib/observe.ts:818`)
  - Issue: Recovery rebuilds a fresh digest from the current transcript and then filters only the digest's current entries by the stranded reservation keys (`observe.ts:818-837`). If an async stdout failure reserves several open-turn entries and `turn_ended: success` arrives before retry, the terminal observation projection emits only the final substantive entry and moves the other reserved entries to recovery pointers (`src/transcript/session-observer/lib/digest.ts:593-629`). A direct reproduction reserved three entry keys, appended the terminal, and replayed only the final key; the other two appeared only as pointers. This contradicts the specified delivery-uncertain replay with the same original entry keys and can omit content from the explicit crash-window replay.
  - Fix: Reconstruct the uncertain replay from the pending reservation's expected/intended frame range and exact `entryKeys`, independent of later lifecycle projection. Return every reserved key in source order with `delivery: uncertain`, or fail closed with a dedicated recovery outcome if any key cannot be reconstructed. Add an integration test that forces async output failure for multiple open-turn entries, appends a terminal before retry, and asserts the replay entry-key set exactly equals the reservation.
  - Requirement: FR2, FR6

- **I2 — Stateless Cursor `review` bypasses bounded stability confirmation** (`src/transcript/session-observer/session-observer.ts:648`)
  - Issue: Unmarked Cursor review calls `buildCursorReviewDigest`, performs one scan, supplies `cursorState: null`, and never performs the required bounded confirmation (`session-observer.ts:648-690`, `801-824`, `930-952`). Only `review --mark-read` routes through `observeCatchUp` and its confirmation path (`session-observer.ts:748-763`). A direct reproduction against a closed, non-terminal assistant record showed `review` exiting 0 with zero entries and `content: buffered`, while `catch-up` on the same transcript confirmed and returned the stable assistant entry. Ordinary stateless review therefore cannot deliver the project's core pre-terminal observation behavior.
  - Fix: Add a read-only two-scan review path that waits at most one configured stability interval and constructs an ephemeral confirmed candidate without creating Cursor state or a delivery reservation. Route both pinned and ranked Cursor review through it, and add tests for open stable content, prefix change during confirmation, and absence of state mutation.
  - Requirement: FR2, FR5

- **I3 — Cursor watch can claim healthy after failed or unverified polling** (`src/transcript/session-observer/lib/watch.ts:1249`)
  - Issue: `pollTargets` silently ignores transcript `stat` failures and leaves the prior healthy status unchanged (`watch.ts:1249-1255`); subsequent heartbeats derive health solely from that stale target state (`watch.ts:472-507`). A direct injected-stat reproduction produced eleven failed poll stats while the heartbeat still reported both watcher and target `healthy: true`. Separately, `watch-ctl status` treats only blocked/stale/error status as unhealthy, so `delivery: uncertain` with `health: unknown` produces no health reason and is reported healthy (`src/transcript/session-observer/session-observer.ts:1607-1635`). This makes poll health and crash ambiguity appear verified when they are not.
  - Fix: Record a failed Cursor metadata poll as `health: error` or `stale` with structural error metadata, persist it to the durable target, and clear it only after a successful stat/read/continuity verification. Make heartbeat and `watch-ctl status` use the same health predicate, treating `unknown` and unresolved `delivery: uncertain` as non-healthy. Add virtual-clock tests for repeated stat failure, recovery on a later successful poll, and uncertain/unknown watch-control status.
  - Requirement: FR5, FR7
