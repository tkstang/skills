### Important

- **Exact Cursor identity resolution rereads every transcript body without an aggregate bound** (`src/transcript/session-observer/lib/locate.ts:945`)
  - Issue: Every stateful Cursor identity resolution calls
    `cursorSessionCanonicalPaths`, which enumerates every project transcript and
    invokes `extractMeta` for each one. `extractMeta` unconditionally calls
    `readRecords` (`src/transcript/core/runtimes.ts:611`), and `readRecords`
    reads the entire file into one string, splits it, and materializes every
    parsed record (`src/transcript/core/runtimes.ts:473`). Cursor's metadata
    branch then ignores those records and derives the session ID solely from
    the path (`src/transcript/core/runtimes.ts:682`). A single large transcript,
    or many accumulated transcripts, can therefore impose unbounded memory and
    aggregate I/O before an exact stateful read or watch begins. This is a
    shipped P1 bounded-resource contract gap, not merely probe overhead.
  - Fix: Derive Cursor session IDs directly from canonical transcript paths
    without reading transcript content. Bound or cache the duplicate-session
    index across project directories with a finite entry/time budget and a
    fail-visible diagnostic when that budget is exceeded. Add a regression
    using many transcripts plus a large transcript that proves exact identity
    resolution does not read their bodies and remains finitely bounded.
  - Requirement: FR1, NFR5

### Medium

- **Wake-probe provider-state preservation resets limits for every top-level entry** (`scripts/probe-cursor-wake-surfaces.mjs:522`)
  - Issue: `snapshotProviderState` fingerprints every top-level entry under
    both provider roots, while `fingerprintProviderEntry` creates fresh
    512-entry and 64 MiB counters per call. The post-run preservation check
    fingerprints every pre-existing entry again with new counters
    (`scripts/probe-cursor-wake-surfaces.mjs:704`). Because the initial scan
    occurs before the provider process timeout begins, arbitrarily many
    individually in-bounds entries can force unbounded aggregate I/O and keep a
    supposedly finite release probe from reaching provider execution.
  - Fix: Share an aggregate entry, byte, and elapsed-time budget across both
    roots and the post-run preservation check. Fail visibly before provider
    launch when the aggregate budget is exceeded, and add a regression with
    enough individually valid entries to cross that bound.
  - Requirement: FR9, NFR5, NFR6
