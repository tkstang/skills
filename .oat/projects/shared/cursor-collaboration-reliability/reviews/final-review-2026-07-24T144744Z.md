## Findings

### Critical

- **Public Cursor arm creates an active v6 lease without the required initial identity/continuity proof** (`skills/session-observer-collab/scripts/collab-control.mjs:134`)
  - Issue: `arm()` canonicalizes only the supplied path and always persists
    `peerContinuity: null` at lines 197-220, including for a nonzero Cursor
    frame cursor. `validateLease()` permits that null checkpoint
    (`skills/session-observer-collab/scripts/lib/lease-state.mjs:357`), and
    `verifyAdapterPeerContinuity()` treats it as verified without checking file
    identity or bytes
    (`skills/session-observer-collab/scripts/lib/runtime-adapter.mjs:84`).
    `observeCursorCompletion()` then constructs `strength: 'exact'` from the
    lease's supplied session/path values instead of resolving that identity
    (`skills/session-observer-collab/scripts/lib/selected-prefix.mjs:143`).
    A direct reproduction armed against inode A, replaced the same canonical
    path with inode B before the first Stop hook, and still emitted a wake for
    B's frames. The same arm surface also accepts a `peerSession` that does not
    match the Cursor transcript path. This violates the v6 design rule that
    every Cursor frame lease has a matching path/device/inode/prefix
    checkpoint and lets an unproved or replaced peer own the private cursor.
  - Fix: Resolve and validate the Cursor peer session/path during `arm`, scan
    through the requested safe frame boundary, and atomically persist a
    non-null checkpoint even for cursor zero. Require that checkpoint in
    schema-v6 validation and make existing null-checkpoint Cursor leases
    require explicit re-arm. Add public-arm tests for session/path mismatch,
    cursor beyond the safe prefix, and same-path shrink/rewrite/inode
    replacement before the first hook.
  - Requirement: FR8, NFR1; Collaboration Lease v6 validation rules

- **A slow observation can claim and emit a wake after its wait deadline and lease expiry** (`skills/session-observer-collab/scripts/hooks/cursor-stop.mjs:237`)
  - Issue: Both owner hooks capture `currentNow` in the loop condition, await
    observation and prefix verification, then pass the stale pre-observation
    value into `claimAdapterTrigger`
    (`skills/session-observer-collab/scripts/hooks/cursor-stop.mjs:264`,
    `skills/session-observer-collab/scripts/hooks/codex-stop.mjs:278`).
    The trigger CAS evaluates expiry against that caller-supplied stale value
    (`skills/session-observer-collab/scripts/lib/lease-state.mjs:657`). A
    deterministic reproduction started observation at time 1001 for a lease
    whose deadline and expiry were 1010, advanced the clock to 1011 inside
    `observe`, and still received a `followup_message`. A large Cursor scan,
    delayed filesystem, or delayed pre-CAS verification can therefore spend
    continuation budget and inject automatic control after its authorization
    window closed.
  - Fix: Refresh the clock after every awaited observation/update and
    immediately before the CAS; reject when the fresh time reaches either the
    stored wait deadline or lease expiry. Ensure the CAS receives or obtains
    that fresh value rather than a loop-entry timestamp. Add Cursor-owner and
    Codex-owner tests where observation and pre-CAS verification cross the
    deadline/expiry and assert no wake, no budget spend, and an idle/expired
    lease.
  - Requirement: FR8, NFR1, NFR5

### Important

- **Cursor discovery still reads every candidate body before exact-session filtering** (`src/transcript/session-observer/lib/locate.ts:685`)
  - Issue: `collectCursorAgentTranscripts()` eagerly materializes complete
    directory listings, and `discoverCursor()` classifies every direct and
    recent fallback candidate before its caller can filter by session
    (`src/transcript/session-observer/lib/locate.ts:816`). Every cache miss
    reaches `candidateDerivedFields()`, which calls whole-file `readRecords()`
    (`src/transcript/session-observer/lib/locate.ts:239`;
    `src/transcript/core/runtimes.ts:470`). Even an exact pin uses
    `findSessionCandidate()`, which calls full `discover()` and filters only
    afterward (`src/transcript/session-observer/lib/locate.ts:1216`). Thus one
    large sibling transcript or many accumulated sessions can consume
    unbounded memory/I/O before the bounded path-only duplicate index runs.
    The p08-t15 regression adds its large siblings only after calling
    `discover()`, so it proves the inner index is path-only but does not cover
    the public locate/observe path.
  - Fix: Resolve an explicit Cursor session pin by bounded path metadata before
    classifying unrelated candidates. Stream and aggregate-bound generic
    discovery, and classify only the bounded set actually needed for ranking.
    Add a regression that creates many/large sibling transcripts before the
    public discovery or pinned-observe call and proves their bodies are not
    read.
  - Requirement: FR1, NFR5

- **Unreadable duplicate-index subtrees are silently treated as a complete uniqueness proof** (`src/transcript/session-observer/lib/locate.ts:983`)
  - Issue: The duplicate index catches every project/session `opendir` failure
    and continues, while its outer catch returns the partial set with
    `failure: null` (`src/transcript/session-observer/lib/locate.ts:1037`).
    `resolveCursorIdentity()` can then add only the selected path and promote
    it to `strength: 'exact'`. A direct reproduction placed the same session
    under a second project, made that project's `agent-transcripts` directory
    unreadable, and received `strength: 'exact'` with no reasons. Permission or
    traversal failures can therefore hide a duplicate and defeat the
    fail-visible ambiguity contract.
  - Fix: Continue only for explicitly benign absence cases such as `ENOENT`
    where the store shape permits them. Return an
    `IDENTITY_INDEX_INCOMPLETE`-style failure for permission, iteration, and
    unexpected I/O errors, include it in the hard-failure set, and add
    root/project/session traversal-failure regressions that keep identity
    non-exact.
  - Requirement: FR1, NFR1

### Medium

- **The Cursor max-runtime regression uses a scheduler-sensitive wall-clock upper bound** (`tests/session-observer/watch.test.ts:1532`)
  - Issue: The test asserts that a real `Date.now()` interval remains below
    400 ms. During the first ordinary full-suite run it took 513 ms and failed;
    the isolated rerun completed in 172 ms and the subsequent full rerun
    passed. This is environmental scheduler latency, not a deterministic
    assertion about the watch loop, so the release suite can fail under load
    despite unchanged behavior.
  - Fix: Drive the watch deadline with the existing injectable/virtual clock
    and assert requested waits and state transitions, or otherwise isolate
    elapsed-time integration coverage from the deterministic unit gate. Retain
    a bounded functional assertion without a host-scheduling threshold.
  - Requirement: NFR6
