## Findings

### Critical

- **A completion wake can be authorized from a stale success scan after the
  selected range becomes non-successful**
  (`skills/session-observer-collab/scripts/hooks/cursor-stop.mjs:214`;
  `skills/session-observer-collab/scripts/hooks/codex-stop.mjs:226`)
  - Issue: Both hooks first scan and classify a Cursor range in
    `defaultObserve()`, then independently rescan in `cursorCheckpoint()` before
    the lease CAS. The second scan verifies only the lease's previously
    committed prefix. It does not verify that the newly selected
    terminal-success range still matches the bytes that produced the selection.
    A same-inode rewrite after the private cursor can therefore change
    `turn_ended.status` from `success` to a non-success value between those
    reads; `cursorCheckpoint()` hashes the changed bytes, the CAS persists that
    new checkpoint, and the hook still spends continuation budget and emits the
    wake selected from the stale success digest. A direct shipped-runtime probe
    changed `success` to `unknown` in this window and observed
    `wakeEmitted: true`, lease state `triggered`, and
    `continuationCount: 1`.
  - Fix: Carry a trusted selected-prefix byte boundary, hash, device, and inode
    from the observation scan into the selection result. Immediately before the
    CAS, re-read that exact bounded prefix and require it to equal the observed
    snapshot; use the same verified snapshot as the proposed lease checkpoint.
    Any mismatch must produce no wake, no budget spend, and no cursor advance.
    Share this logic between both hooks and add regressions that mutate a
    selected success terminal to every non-success class between observation
    and CAS.
  - Requirement: FR3, FR4, FR8, NFR1, NFR6

### Important

- **Later appends restart the stateful stability candidate instead of confirming
  its bounded prefix**
  (`src/transcript/session-observer/lib/observe.ts:839`)
  - Issue: The confirmatory scan correctly hashes only
    `firstObservation.prefixBytes`, but then checkpoints
    `secondObservation`, whose boundary and entry-key set extend through every
    later safe frame. `checkpointCursorCandidate()` therefore treats ordinary
    growth as a replacement candidate. Even if the first candidate were
    preserved, delivery is currently reserved only when
    `digest.range.nextIndex` equals the second scan's full safe boundary
    (`src/transcript/session-observer/lib/observe.ts:969`), so a confirmed
    prefix cannot advance while a later frame remains buffered. A shipped
    runtime probe appended substantive frame B during frame A's one-second
    confirmation interval; after two scans it returned no entries, buffered
    both frames, and restarted the candidate through B. This contradicts the
    explicit design rule that growth after A's boundary must not restart A.
  - Fix: Confirm the original observation's boundary and keys with the second
    scan's `verifiedPrefixSha256`. Build and reserve the continuity checkpoint
    through the digest's verified `nextIndex`, even when the current file has
    later safe bytes, while retaining those later bytes as the next candidate.
    Add one-shot and foreground-watch tests for growth during confirmation and
    continuous growth through `max-pending-sec`.
  - Requirement: FR2, FR7, NFR6

- **A completed Cursor turn is permanently missed when a later turn is already
  pending**
  (`skills/session-observer-collab/scripts/lib/completion-selection.mjs:118`)
  - Issue: The completion projector correctly emits the terminal-successful
    prefix and holds `nextIndex` at the following pending turn
    (`src/transcript/session-observer/lib/digest.ts:548`), but
    `validateV2Digest()` rejects every digest whose `nextIndex` is below
    `totalFrames` or whose suffix is buffered. With frames 0-2 forming a
    successful turn and frames 3-4 forming a pending turn, the shipped digest
    contained the completed entry at terminal frame 2 and a safe next cursor of
    3, yet the selector threw `observer result must contain complete frame range
accounting`. The real Cursor hook converted that into
    `diagnostic: observer-invalid`, idled the lease at cursor 0, and emitted no
    wake.
  - Fix: Accept a complete, unsliced terminal-successful prefix followed only
    by a structurally valid `stability-wait` suffix. Select and checkpoint the
    completed prefix while leaving the later open turn unread. Continue to
    reject malformed, partial, tail-sliced, discontinuous, or unaccounted
    ranges. Add Cursor-owner and Codex-owner hook tests for success followed by
    a pending turn.
  - Requirement: FR3, FR8, NFR6

- **Exit-gate bookkeeping makes the committed Cursor evidence gate fail**
  (`.oat/projects/shared/cursor-collaboration-reliability/state.md:56`)
  - Issue: The accepted exit-gate commits persist a user-specific absolute
    receipt path, a temporary marker path, raw run/launch IDs, and full
    fingerprints in tracked lifecycle artifacts. The evidence validator
    deliberately includes changed Markdown outside `reviews/`
    (`scripts/validate-cursor-evidence.mjs:607`), so the current branch fails
    with seven findings across `state.md` and `project-log.md`. Several
    `raw-identity` hits are over-broad matches on structural git/config hashes,
    but the `/Users/...` receipt path is actual machine-local leakage and the
    required final evidence gate is red.
  - Fix: Keep receipt and temporary-marker paths in local-only state or persist
    repo-relative/redacted values in tracked artifacts. Define an explicit
    validator policy for gate IDs, git SHAs, and typed structural fingerprints
    so those values are either safely redacted or narrowly distinguished from
    transcript session/lease identities. Add an end-to-end regression that
    performs accepted gate bookkeeping and then runs the evidence validator.
  - Requirement: FR9, NFR2, NFR6
