## Provider-State Containment Verification

The implementation now treats Cursor provider state as part of the probe's explicit safety boundary:

- It resolves the projects and chats roots from `CURSOR_DATA_DIR` or `HOME/.cursor`, declares the `encoded-workspace` and `workspace-metadata` ownership policies, and snapshots both roots before provider invocation.
- A root must be an absolute, real directory and not a symlink. The probe records its realpath, device, inode, birthtime fingerprint, and exact direct-child name set, then revalidates root identity before cleanup.
- Project ownership uses the exact Cursor direct-child mapping for both the raw and canonical workspace paths. The compact-name branch matches the installed Cursor Agent's sanitizer and SHA-256 seven-character suffix behavior for paths exceeding the worker's threshold.
- Chat ownership requires bounded JSON metadata containing the exact raw or canonical workspace path.
- Only new direct children are candidates. Each candidate must remain a direct realpath child, be a directory rather than a symlink, have a birthtime within the bounded provider-run window, contain no symlink escapes, and remain within the bounded inspection limits.
- Immediately before deletion, ownership and the artifact's device and inode are rechecked. Cleanup targets only the exact proven-owned directory with non-forced removal and verifies that it is absent afterward.
- An unrelated, ambiguous, changed, or symlinked artifact is preserved and makes cleanup fail closed. An injected removal failure remains visible and prevents a successful evidence label.
- Timeout handling terminates the provider process group with TERM and then KILL if needed; the same provider-state cleanup still runs from the finalization path.
- The validator checks the declared roots and truthful safety fields and executes a synthetic isolation contract that exercises both roots, exact ownership, preservation of pre-existing entries, exact removal, and post-run absence.

The installed Cursor Agent version `2026.07.23-e383d2b` was inspected read-only. Its project-directory sanitizer, length threshold, truncation length, and seven-character SHA-256 suffix agree with the probe implementation used in the live environment.

The focused tests additionally cover exact external-state removal, timeout cleanup, pre-existing-state preservation, an escaping symlink, an unrelated ambiguous entry, injected deletion failure, a symlinked provider root, the executable isolation contract, evidence validation, and both probe recipes.
