## Findings

### Critical

- **C1 — Cursor delivery commits before native stdout completion**
  (`src/transcript/session-observer/session-observer.ts:323`)
  - Issue: `writeStdout()` calls native `process.stdout.write()` without a
    callback and treats a `true` boolean return as completed delivery.
    `emitCursorResult()` then commits the reserved checkpoint and immediately
    exits (`session-observer.ts:618-647`). The watch path likewise commits as
    soon as a non-Promise sink returns
    (`src/transcript/session-observer/lib/watch.ts:931-956`). Native stream
    completion and asynchronous errors are callback/event based, so a queued
    write or later `EPIPE` can leave the checkpoint committed even though the
    consumer never received the digest. Restart then suppresses that content.
  - Fix: Make the production stdout adapter resolve only from the write
    callback while listening for an error during the pending write. Give the
    watch dependency an explicit awaited completion contract and add real
    boolean-returning delayed-callback and asynchronous-error regressions for
    one-shot and watch delivery.
  - Requirement: FR6, NFR1.

- **C2 — A delivered stability candidate can permanently starve later
  same-turn content**
  (`src/transcript/session-observer/lib/observe.ts:960`)
  - Issue: When a stored candidate exists, the next observation is rebuilt at
    that old boundary (`observe.ts:960-979`) before newly appended frames are
    considered. After delivering `A` and appending `B` in the same open turn,
    repeated catch-up returned no entries, kept `throughFrameIndex: 1`, and
    left `nextIndex: 2`; `B` never became deliverable. The post-reservation
    next-candidate logic (`observe.ts:1209-1245`) cannot recover from this
    already-delivered stored boundary.
  - Fix: Never reinstall or reconfirm a candidate whose entry keys were
    committed. After confirming the old boundary, derive and persist the next
    candidate from the safe suffix, then add repeated-scan coverage for `A`
    followed by `B` in the same turn.
  - Requirement: FR2, FR6.

- **C3 — A safe no-op suffix makes an earlier substantive completion
  unclaimable**
  (`skills/session-observer-collab/scripts/lib/selected-prefix.mjs:192`)
  - Issue: `observeCursorCompletion()` snapshots
    `digest.range.nextIndex`, which is the end of the full safe scan. The
    completion selector can correctly choose an earlier substantive success,
    but `claimAdapterTrigger()` requires the checkpoint's
    `nextFrameIndex` to equal that earlier `peerCursor`
    (`skills/session-observer-collab/scripts/lib/runtime-adapter.mjs:166-175`).
    A three-frame substantive success followed by a closed no-op turn produced
    `peerCursor: 3` and `selectedPrefix.nextFrameIndex: 6`; both owner routes
    rejected the claim and emitted no wake.
  - Fix: Bind the verified checkpoint to the selector's chosen completion
    boundary, not the full digest boundary, while retaining full-suffix
    accounting. Add Cursor-owner and Codex-owner tests for substantive success
    followed by no-op, automatic acknowledgement, and metadata-only suffixes.
  - Requirement: FR8.

### Important

- **I1 — An unresolved transcript path can still become exact identity**
  (`src/transcript/session-observer/lib/locate.ts:977`)
  - Issue: Failed `realpath()` calls are replaced with lexical paths for the
    cwd, transcript, and supported root (`locate.ts:977-983`). A nonexistent
    transcript under the lexical store root, with otherwise matching cwd and
    session evidence, reproduced `strength: "exact"` with no reasons. Stateful
    observation can therefore cross the exact-identity gate without proving a
    canonical existing transcript.
  - Fix: Treat any required canonicalization failure as diagnostic or
    ambiguous, and require successful realpath plus containment before exact
    state ownership. Add disappearance and symlink-swap tests.
  - Requirement: FR1, NFR1.

- **I2 — Unsupported top-level assistant content is promoted as substantive**
  (`src/transcript/core/cursor-analysis.ts:121`)
  - Issue: The measured Cursor baseline is top-level `role` with nested
    `message.content`, but `contentBlocks()` falls back to the entire record
    when `message` is absent. A record containing unsupported top-level
    `content` was classified `substantive` and selected as the final successful
    entry (`cursor-analysis.ts:162-179`, `221-237`). Unknown provider shapes can
    therefore surface as user-visible content and authorize collaboration.
  - Fix: Mark missing/non-object `message` as unsupported unless that shape is
    separately evidence-gated, documented, and tested.
  - Requirement: FR2, FR3, FR9.

- **I3 — Watch runtime limits can overrun by an unbudgeted stability wait**
  (`src/transcript/session-observer/lib/watch.ts:1686`)
  - Issue: The deadline is checked only around a whole tick
    (`watch.ts:1686-1697`, `1758-1774`), while baseline/pending observation
    calls receive the unrestricted sleep dependency
    (`watch.ts:1014-1029`, `1519-1535`). A 60 ms configured runtime with a
    1,000 ms stability wait reproduced `reason: "max-runtime"` only after
    1,000 ms elapsed.
  - Fix: Pass a remaining-time budget through observer and flush operations,
    cap every sleep to it, and stop without starting work that cannot fit.
  - Requirement: FR7, NFR5.

- **I4 — The acceptance probe timeout is not a hard process bound**
  (`scripts/probe-cursor-acceptance.mjs:52`)
  - Issue: The timer sends only `SIGTERM` and the promise resolves only on
    `close` (`probe-cursor-acceptance.mjs:67-104`). A child that ignored
    `SIGTERM` with `timeoutMs: 30` returned after 328 ms only because the child
    exited itself; an indefinitely resistant process or descendant can hang
    the evidence run.
  - Fix: Use a bounded TERM-to-KILL escalation, terminate the process group
    where supported, and resolve after a finite kill deadline. Exercise the
    real termination path rather than injecting only `timedOut`.
  - Requirement: FR9, NFR5, NFR6.

- **I5 — Current gate bookkeeping fails the repository evidence validator**
  (`.oat/projects/shared/cursor-collaboration-reliability/state.md:57`)
  - Issue: The accepted launch wrote a machine-local
    `/var/folders/.../oat-gate-runs/...` marker, and
    `implementation.md:1368` repeats an opaque implementation fingerprint in
    an untyped prose form. The required command currently fails with two
    `raw-identity` findings, regressing the p07-t04 acceptance criterion and
    contradicting the prior passing review.
  - Fix: Persist the marker in the approved logical `system-temp:` form and
    render fingerprints only in an approved typed field form. Add the
    accepted-launch bookkeeping path to the evidence-validation regression.
  - Requirement: FR9, NFR2, NFR6.

  - Fix: Require a passed provider-version row for live promotion or downgrade

- **M4 — Provider cleanup does not verify pre-existing state was unchanged**

    content inside a pre-existing entry while cleanup still reports success.
  - Fix: Fingerprint relevant pre-existing entries before and after the probe,
    or narrow the safety claim to removal of newly created artifacts.
  - Requirement: FR9, NFR2, NFR6.
