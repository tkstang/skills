### Important

- **Declaration validation permits external source-root symlinks and arbitrary repository replacement targets** (`scripts/lib/packaging.ts:111`)
  - Issue: `assertTarget` checks only that `target.output` is relative. A standalone declaration such as `output: "package.json"` is accepted, and plugin identifiers are not constrained to a safe path segment. `buildDeclaredDistributions` also uses `stat` on the declared source root at line 579, so a source-root symlink is followed even though nested symlinks are rejected. An adversarial probe confirmed that `package.json` is accepted as a standalone output and a `src/skills/<owner>` symlink to a directory outside `repoRoot` is packaged successfully. A declaration typo or compromised source layout can therefore replace unrelated repository content or ingest files outside the declared repository boundary, contrary to the design's `skills/<name>` / `plugins/<plugin>/skills/<name>` ownership and symlink/source-escape rules.
  - Fix: Require standalone output to equal `skills/${target.name}`, validate plugin as a single safe identifier, and derive plugin output from validated fields instead of trusting a free-form path. Use `lstat`/`realpath` containment checks for the source root and every allowed source root before walking or bundling; reject a root symlink and any resolved root outside `repoRoot`. Add negative tests for arbitrary standalone outputs, traversing plugin identifiers, source-root symlinks, and allowed-root symlinks.
  - Requirement: p01-t02 safe installed-unit containment; design lines 37-40 and 69-71; plan line 114.

- **A replacement failure after the first unit leaves the declared distribution partially updated** (`scripts/lib/packaging.ts:723`)
  - Issue: `writeDeclaredDistributions` commits units one at a time, while `replaceDeclaredDistribution` deletes each successful unit's backup before the next unit starts. An injected failure on the second unit confirmed that the first unit remained on the new payload while the second was restored to its prior payload. This can split standalone and plugin forms, or two owners in one build, across different source/version states even though all units were staged together. It violates the phase's failure-atomic replacement and single-version distribution contract.
  - Fix: Treat the built unit set as one replacement transaction: move all existing outputs to retained backups, install every staged unit, roll back every installed/moved unit if any operation fails, and remove backups only after the entire set succeeds. Preserve and report every recovery path when rollback is incomplete. Add a multi-unit regression that fails after one successful replacement and verifies that all prior inventories are restored.
  - Requirement: p01-t02 safe replacement; discovery line 63; design line 71; plan line 114.
