### Important

- **Required observer detection rejects a supported alternate installation form** (`src/skills/session-observer-collab/SKILL.md:24`)
  - Issue: The canonical instruction contains one `{{skill:session-observer}}` slot, which packaging resolves to `session-observer` for the standalone collab output and `observer` for the consensus-plugin output. Each generated preflight therefore checks only its colocated/preferred name. A standalone `session-observer-collab` paired with consensus `observer`, or a plugin `observer-collab` paired with standalone `session-observer`, can stop even though the required workflow is installed in a supported form. This misses p03-t04's explicit requirement to accept documented standalone or plugin forms and makes mixed supported installations unusable.
  - Fix: Render or author a prerequisite identity set that checks the canonical standalone name plus the plugin-local or qualified consensus form supported by the host. Stop only after none of the documented forms is present. Add negative and positive installed-boundary cases for both cross-form pairings, while preserving the no-fetch/no-install behavior and canonical install guidance.
  - Requirement: p03-t04 required-skill preflight; discovery safeguard and design section 4.

- **Provider preflight treats every successful version command as compatible** (`src/plugins/consensus/provider-cli/probe.ts:114`)
  - Issue: After any zero-exit `--version`, the probe returns `ready` with the raw first output line. `runPreflight` then reports `usable: true` based only on that status and attaches static adapter capabilities. There is no parsed minimum version, compatibility comparison, or operation-specific capability probe. A synthetic `codex 0.0.1` response was independently accepted as usable with the current code. This misses p03-t04's requirement to establish reliable minimum versions and operation-specific capabilities before work, so an old or incompatible selected CLI passes preflight and fails later during the paid/provider operation.
  - Fix: Declare evidence-backed minimum compatible versions or local capability checks per provider and operation, parse and compare the probed version, and return a non-usable diagnostic when compatibility cannot be established. Make preflight accept the operation/capability set required by its caller rather than treating the adapter's static declaration as proof about the installed binary. Add deterministic cases for below-minimum, unparseable, compatible, and missing-required-capability outputs; keep the selected-provider-only and sanitized-environment guarantees.
  - Requirement: p03-t04 selected-CLI preflight; design section 7.
