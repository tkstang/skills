## Proposed changes

Keep the plan's existing exclusions: no JSONL streaming protocol, separate usage ledger, price configuration, delivery-ack subsystem, generic filesystem framework, prose snapshots or automated retro evaluator. The first Opus review suggested a permanent test matching prose state names to the TypeScript union. Root declines that mechanism: perform the explicit acceptance comparison with representative evidence instead; it proves current fidelity without owning a brittle prose-equality assertion. No material simplification of runtime behavior is required before implementation. Update factual review findings separately; this ledger does not prove correctness.

## Risks of simplifying

Removing completeness/identity/collision checks would undermine the frozen artifact. Dropping stress runs or independent reviews would violate accepted requirements. Treating usage as one sum or terminal failures as messages would erase necessary semantic distinctions.
