### Important

- **Codex function-call arguments are never parsed or diagnosed** (`src/shared/transcript/activity/codex.ts:209`)
  - Issue: `responseItemActivity` copies `payload.arguments` or `payload.input` into the single `arguments` field and returns no argument-parse diagnostic. For observed `function_call` records, this leaves valid JSON arguments as a string; malformed JSON is likewise retained as a string with no indication that parsing failed. The phase contract requires parsed and original arguments to coexist and requires malformed argument JSON to keep the call with a parse diagnostic (`discovery.md:68`, `design.md:91`). The captured integration path confirms the gap: `fixture-call-function` exposes `arguments` as `"{\"cmd\":\"printf fixture\"}"`, and `ActivityDiagnosticCode` has no argument-parse diagnostic.
  - Fix: Add distinct original-carrier and parsed-argument fields (or an equivalently unambiguous typed representation). Parse only the native string field that is documented as JSON, retain the exact original string/object carrier, and emit a stable content-free diagnostic at the call locator when parsing fails. Add valid-object and malformed-JSON regressions for function/custom carriers and verify projection budgets both representations without leaking parser error text.
  - Requirement: Discovery success criterion 3; design Native extractors and correlation; p02-t02.

- **Detailed reads discard required source snapshot provenance and the original carrier** (`src/shared/transcript/runtimes.ts:1120`)
  - Issue: `DetailedTranscriptRead` returns only `records` and `diagnostics`, each decoded record returns only the parsed object/index/line, and `readActivityReport` therefore cannot include capture time or source byte length. The approved amendment explicitly retained original carriers and source-size metadata (`plan.md:49`), while the design requires an internal original carrier and an activity report with capture time/byte length (`design.md:85-87`, `design.md:139-142`). Without these fields, consumers cannot state which captured view the locators and captured-source counts describe, and exact source carrier evidence has already been irreversibly normalized before extraction.
  - Fix: Extend the detailed read with capture timestamp and byte length from the same completed file read, retain the original per-record carrier internally without placing it in diagnostics or projected output, and propagate only the bounded report-level snapshot metadata into `ActivityReport`. Preserve the legacy `readRecords()` projection and warning bytes. Add regressions for empty input, multibyte UTF-8, CRLF, malformed lines, and valid no-newline tails that prove byte length/capture metadata and ensure diagnostics still contain only kind and line.
  - Requirement: Approved scope refinement; design Detailed source reader and Activity report data model; p02-t01/p02-t04.
