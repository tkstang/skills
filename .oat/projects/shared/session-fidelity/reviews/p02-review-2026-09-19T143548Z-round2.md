### Important

- **The serialized-size guard cannot bound diagnostic-heavy reports** (`src/shared/transcript/activity/project.ts:408`)
  - Issue: `buildReport` always includes every range-eligible coverage entry and diagnostic, while the size-reduction loop can remove only event groups. Source parse diagnostics have no decoded `recordIndex`, so the range filter also treats every one as source-wide. Once those arrays alone exceed the mode byte ceiling, removing all groups still ends in `RangeError('Activity report metadata exceeds the byte limit')` at line 488. A synthetic 1,000-line malformed source reproduces the failure under the 32 KiB watch limit with zero events. This violates the declared bounded-envelope contract and the requirement that the final guard can return a valid minimal report with explicit omissions.
  - Fix: Apply deterministic bounds to diagnostic and coverage entries as part of the final size guard, preserving stable locators for retained entries and adding explicit omitted diagnostic/coverage counts or equivalent bounded coverage status. Ensure the zero-event form remains within the limit and does not throw for a valid activity input. Add a regression with enough malformed records to overflow the metadata-only watch report and assert `renderedBytes <= maxBytes`, deterministic retained diagnostics, and explicit omission accounting.
  - Requirement: Design Classification and projection / Error Handling; p02-t04.

- **Inherited and unknown calls bypass the mode invocation ceiling** (`src/shared/transcript/activity/project.ts:435`)
  - Issue: invocation limiting filters only groups whose call has `ownership === 'owned'`. That ownership rule is correct for `countedInvocations`, but it is also used as the selection predicate, so inherited and unknown calls never consume the 80-call watch/catch-up or 1,024-call review ceiling. A watch projection of 81 small inherited calls displays all 81 at 15,205 bytes with `maxInvocations: 80` and reports no omission. The mode contract says the envelope displays up to the configured number of invocations; excluding inherited history from child invocation counts does not authorize an unbounded number of displayed call groups.
  - Fix: Keep `countedInvocations` ownership-aware, but enforce `maxInvocations` over all delivered call groups that would be displayed. Define deterministic priority across owned, inherited, and unknown groups while preserving explicit failures and recent evidence, then report every removed group through the existing omission fields. Add inherited-only, unknown-only, and mixed-ownership regressions that remain at or below each mode limit without changing captured/delivered ownership counts.
  - Requirement: Design Classification and projection; p02-t04.
