### Minor

- **m1: Direct helper invocation through a symlinked directory silently exits 0 without installing** (`scripts/install-standalone.mjs:317`)
  - Issue: The CLI guard compares `path.resolve(process.argv[1])` with `fileURLToPath(import.meta.url)`. Node realpaths the main module but not `argv[1]`, so `node <symlinked-dir>/scripts/install-standalone.mjs ...` fails the guard and the module returns with exit 0, no output, and no destination change.
  - Evidence: Reproduced with a temporary symlink to the checkout: direct `node` invocation printed nothing and exited 0; the same arguments through `bash <symlink>/install.sh` reached the installer (which then correctly refused the pre-existing destination) because `script_dir` uses `pwd -P`.
  - Impact: Not reachable through the documented `install.sh` procedure. Only undocumented direct `node` use is affected, and it fails silently rather than unsafely.
  - Fix: Compare `realpathSync(process.argv[1])` (guarded for ENOENT) against the module path, or print an explicit `install.sh:` error when the guard fails.

- **m2: Global and system Git configuration is ignored during tag acquisition, and the guide does not say so** (`scripts/install-standalone.mjs:98`)
  - Issue: `GIT_CONFIG_NOSYSTEM=1` and `GIT_CONFIG_GLOBAL=/dev/null` mean user settings such as `http.proxy`, `http.sslCAInfo`, `url.<base>.insteadOf`, `credential.helper`, and `core.sshCommand` do not apply to the fetch from `https://github.com/tkstang/skills.git`. Inherited `GIT_SSL_CAINFO`/`GIT_PROXY_COMMAND` are also scrubbed by the `GIT_*` filter.
  - Impact: Environments that rely on Git config for proxies or private CAs will fail with a raw Git transport error. Environment-variable proxies (`https_proxy`) still work. This is a deliberate isolation consistent with discovery decision 10, so it is an artifact/documentation alignment item, not a code defect.
  - Fix: Add one sentence to the First-party installer section of `documentation/docs/user-guide/installation.md` stating that global/system Git configuration is not consulted and that `--repository` may point at a local mirror when network policy requires it.

- **m3: Node-version failure message names the Consensus CLI in standalone mode** (`install.sh:68`, `install.sh:123`)
  - Issue: `require_node_22` is reused for the standalone dispatch branch, so a Node <22 user running `install.sh --skill ...` sees "required to run the consensus provider CLI".
  - Fix: Parameterize the message or use a neutral phrase ("required by install.sh").

- **m4: Hard-coded 60-second Git timeout surfaces as an opaque `Command failed` error** (`scripts/install-standalone.mjs:111`)
  - Issue: `execFile` kills the fetch after 60s with SIGTERM; the user sees `install.sh: Command failed: git --git-dir ... fetch ...` with no hint that a timeout occurred. A shallow tag fetch of this repository is small, so this is unlikely on normal links.
  - Fix: Detect `error.killed`/`error.signal` and report "timed out after 60s"; optionally raise the cap for the fetch step only.

- **m5: Artifact alignment: `implementation.md` references a `spec.md` that quick mode does not produce** (`.oat/projects/shared/first-party-standalone-installer/implementation.md:499`)
  - Issue: The References list includes `Spec: spec.md`, but the project is `oat_workflow_mode: quick` and `state.md` correctly records Spec as N/A.
  - Fix: Remove the line or mark it "N/A (quick mode)" during closeout bookkeeping.
