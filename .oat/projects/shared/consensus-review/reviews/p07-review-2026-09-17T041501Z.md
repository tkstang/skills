### Important

- **I1 — A selected file can change after evidence capture but before the drift baseline, and the stale evidence is still accepted** (`src/skills/consensus-review/src/run.ts:390`)
  - Issue: `executeBoundedReview` captures the review evidence first, persists it, and only later records `before` with `captureScopeState` at lines 445–449. It never compares that baseline with the hashes in the captured scope. A change in this interval makes `evidence.json` and the scope token describe the old bytes while both the pre-dispatch recheck and post-run comparison use the new bytes as their baseline; the run can therefore complete with `drift.stable: true` after reviewing stale evidence.
  - Evidence: A deterministic no-provider probe captured `reviewed.ts` as SHA-256 `01d09d...`, changed it before the first state scan, then observed baseline SHA-256 `7aa7a5...`; `compareScopeState(before, after)` returned `checked: true, stable: true` with no differences. The focused tests mutate only during the provider turn and do not cover this capture-to-baseline window.
  - Fix: Derive the initial comparison snapshot atomically from the captured versions, or immediately compare the first state scan against the captured selected-path identities and HEAD before selection/dispatch. Fail with zero invocations if they differ. Add a regression that mutates a selected file between `captureScope` and the first scan and proves no provider call occurs.
  - Requirement: design.md “Revalidate selected scope immediately before dispatch,” captured exact content/hash evidence, and p07-t01 authoritative versions plus selected-path drift.

- **I2 — Host provenance is hard-coded unknown while requested model/effort are mislabeled as observed** (`src/skills/consensus-review/src/run.ts:356`)
  - Issue: `ReviewAggregate.authored_by` is typed to permit only `unknown`, and every completed run writes the same unknown record at lines 628–635. There is no structured input for detected or declared author evidence, so available evidence cannot be preserved and partial coverage cannot be represented. Separately, lines 621–625 populate `reviewer.observed.model` and `.effort` from the selected/requested configuration rather than independent provider output. This turns passed options into purported observations and makes the host-owned provenance record misleading.
  - Fix: Accept and persist bounded structured author evidence with `detected | declared | unknown` and explicit coverage, defaulting honestly to unknown when absent. Separate reviewer `selected`/requested and passed options from independently observed identity; keep observed model/effort unknown unless the transport supplies trustworthy evidence. Add mixed/partial/unknown author cases and a test proving an unreported requested model is not marked observed.
  - Requirement: discovery.md decisions 5 and 9; design.md host-owned author provenance and requested/passed versus observed reviewer evidence; p07-t03 preservation of author/reviewer evidence and unknown/partial coverage.

### Medium

- **M1 — Files and document scopes cannot run in an unborn repository** (`src/skills/consensus-review/src/scope.ts:79`)
  - Issue: `captureReviewScope` resolves `HEAD` unconditionally before branching on the selector. `git rev-parse --verify HEAD` fails in a newly initialized repository, so the explicitly supported files/document modes never reach their filesystem-only capture paths.
  - Evidence: In a temporary initialized repository with `draft.txt` but no commit, `captureReviewScope({kind: 'files', paths: ['draft.txt']})` failed with `fatal: Needed a single revision`.
  - Fix: Require HEAD only for `base_branch`. For files/document scopes, represent the absent HEAD explicitly and make state comparison treat creation of the first commit as drift. Add unborn internal-file, internal-document, and external-document coverage.
  - Requirement: design.md Scope Selection: “an unborn repository can still use files/document.”

- **M2 — The persisted scope drops the resolved base-ref identity and the actual comparison identities** (`src/skills/consensus-review/src/scope.ts:94`)
  - Issue: base capture resolves `${ref}^{commit}` but discards `resolvedRef` when constructing `CapturedReviewScope`; the result retains only the requested string, HEAD, and merge base. In addition, the before/after index, status, and selected-path snapshots are reduced to a stable boolean and difference strings in the aggregate. A completed artifact therefore cannot establish which ref commit was reviewed or audit the identities that produced “no change detected.”
  - Fix: Persist the resolved ref commit and the bounded before/after comparison identities (or deterministic hashes of them) in host-owned evidence, while retaining the existing limitation text. Include relevant base blob identities where available and test a ref whose tip differs from its merge base.
  - Requirement: design.md captured evidence for base scope and host aggregate ownership of Git/scope identities and drift coverage.

- **M3 — A final result write failure leaves no labeled diagnostic even when diagnostic persistence is still available** (`src/skills/consensus-review/src/run.ts:659`)
  - Issue: all transport, drift, and validation failures go through `persistDiagnosticFailure`, but a `result.json` exclusive-create collision or other final write error returns `output_failed` directly. The external run directory is left with request/evidence (and potentially provider capture) but no `diagnostic.json`, contrary to the run-state contract that incomplete/defective output is clearly labeled. The existing output-error test deliberately fails only the third write, so a fourth diagnostic write would succeed, but it does not assert one.
  - Fix: On result persistence failure, attempt one exclusive diagnostic write recording `result_persistence_failed`, invocation count, and drift, without rerunning the provider. If that diagnostic write also fails, retain the current explicit output failure and report both errors. Extend the test to assert the diagnostic path and content.
  - Requirement: design.md external state/result contract and p07-t03 host-owned JSON persistence plus output-error diagnostics.
