### Minor

- **Renderer escapes every `.`, `-`, and `!` in prose and inspected-context subjects, which degrades raw-Markdown readability for the instruction-driven receiver** (`src/skills/consensus-review/src/review.ts:804-810`)
  - Issue: `escapeMarkdown` applies `\\$1` to `[`*_{}[\]()<>#+.!|-]` unconditionally. In CommonMark a backslash before any ASCII punctuation is a valid escape and renders correctly, but `oat-review-receive` is instruction-driven and reads raw bytes (`discovery.md:91`), so it sees `Review the bounded receipt fixture\.` and `- src/clean\.ts (`clean-source-v1`)` (`tests/fixtures/consensus-review-receipt/clean-review.md:18-42`). A receiver copying an inspected-context subject literally would carry the backslash into a path. This behavior predates the narrowed range; it is surfaced here because the in-range fixture refresh made it visible and it bears directly on the Medium finding above. Finding locations remain inside code spans and are unaffected.
  - Suggestion: Narrow escaping to positions where the character is syntactically live — `#`, `-`, `+`, and `\d+.` only at line start, `.`/`!` never mid-sentence — or render inspected-context subjects with `inlineCode` like finding locations. Regenerate the two fixtures from the renderer in the same change so the byte-parity test and hashes move together; bump `consensus-review` `metadata.version` and add a changelog line.
