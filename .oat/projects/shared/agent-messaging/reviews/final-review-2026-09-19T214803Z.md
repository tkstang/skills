### Medium

- **The documented arm and re-arm commands pass `--root`, which `collab-control.mjs` silently ignores** (`src/skills/session-observer-collab/references/runtime-claude-code.md:48-49`, `:74-75`, `src/skills/session-observer-collab/src/collab-control.mjs:532-533`)
  - Issue: p05-t06 added a complete arm/enable/launch/re-arm sequence that gives every command `--root <absolute-state-root>`. `delivery enable` and `claude-monitor.mjs` honor that flag, but `collab-control.mjs run()` resolves its root only from the environment (`stateRoot(env)`), and its generic `parseArgs` accepts any `--key value` pair, so `arm --root X` prints `arm: ok` while writing the lease under the default state root. Reproduced with the generated bundles and a scratch `HOME`: following the reference verbatim with a non-default root left `<root>/leases/` empty, wrote the lease to `$HOME/.local/state/session-observer/collab/leases/`, and `delivery enable` then refused with `composed-monitor-inactive`. The same sequence succeeds when the root is supplied through `SESSION_OBSERVER_STATE_DIR` (enable ok, Monitor `duration-complete`, rc=0). The failure is closed, but the operator gets a success message from arm, an unexplained refusal from enable, and a stray live lease in the default root that `assessAutomaticOwnership` will treat as an exact-session continuation owner for standalone messaging in that session. p05-t06's Verify line ("documented commands against CLI parsing") did not catch it because no test parses the reference's commands against `collab-control`.
  - Fix: pick one contract and make the reference and CLI agree. Preferred: have `collab-control.mjs` accept an absolute `--root` (validated with `validateAbsolutePath`, overriding the environment) for parity with the Monitor and the messaging CLI, and reject unknown options so a future mismatch fails loudly. Minimal alternative: remove `--root` from the two `arm` examples and state that the observer root comes from `SESSION_OBSERVER_STATE_DIR` / XDG, with the same value passed as `--root` to the other two commands. Either way add a test that runs the documented sequence (arm, enable, Monitor) against one non-default temp root using the generated bundles.
  - Requirement: plan p05-t06 (complete, consistent invocation guidance; documented commands verified against CLI parsing).

- **No executed-bundle symlink test for the Codex and Cursor Stop entrypoints** (`src/skills/session-observer-collab/src/hooks/codex-stop.mjs:610-615`, `src/skills/session-observer-collab/src/hooks/cursor-stop.mjs:372-377`)
  - Issue: p05-t01 asked to "execute each generated entrypoint through a symlinked directory and prove it runs". The Monitor and both messaging hooks have such tests; the two Stop hooks do not, and because they emit nothing when there is no eligible lease, a black-box run cannot distinguish "ran and allowed" from "guard false" (confirmed: identical silent rc=0 on real and symlinked paths). - **Entrypoint guards throw at import time when `argv[1]` is not an existing path** (`src/skills/session-observer-collab/src/claude-monitor.mjs:576-579`, `src/skills/agent-messaging/src/hooks/claude-code.ts:89-93`, `src/skills/agent-messaging/src/hooks/codex.ts:91-95`, both Stop hooks)

Direct execution and the Vitest suite are unaffected because `argv[1]` is always a real file there; the pre-existing manual CLI has the same shape. Impact is limited to embedding or tooling that imports these modules under a synthetic `argv[1]`.
  - Suggestion: wrap the comparison in a small shared `isMainModule()` helper that returns `false` on `ENOENT`/`ENOTDIR` rather than throwing, and use it in all six entrypoints.

- **New packaging tests leave their temporary install directories behind** (`src/skills/session-observer-collab/src/claude-monitor-packaging.test.ts:46-51`)
  - Issue: each run creates `claude-monitor-installed-*` plus a `-linked` symlink under the OS temp directory and never removes them; `src/AGENTS.md` asks tests to clean up their known fixture paths.
  - Suggestion: remove both paths in a `finally` block (or `afterEach`) with `rm(..., { recursive: true, force: true })`.
