### Important

- **Historical observer bundles are treated as composition-capable** (`src/skills/agent-messaging/src/registration.ts:126`)
  - Issue: `recognizedObserverLauncher` accepts every structurally valid observer launcher/manifest, including bundles installed before Phase 3. It verifies the generic owner marker, opaque version string, file-list shape, and file existence, but no Phase 3 composition capability or content digest. `assessAutomaticOwnership` then treats that boolean as proof of a “verified composed-capable adapter” and permits `observer-collab` ownership at lines 537-597. An older observer Stop bundle does not read messaging activations or shared claims, so enabling against it leaves inbox-first delivery and the shared continuation cap absent while reporting composition as enabled. This violates p03-t02's explicit requirement that legacy/uncomposed owners refuse and that a matching lease alone is insufficient (`plan.md:579-595`).
  - Fix: add a versioned composition capability to the installed observer bundle manifest (and preferably verify the installed file digest), require that capability during inventory, and reject pre-capability manifests as legacy/uncomposed. Add a fixture built with the pre-Phase-3 manifest/bundle shape and prove enablement fails closed.
  - Requirement: p03-t02 verified composed-capable adapter and legacy-owner refusal.

- **Registration can switch away from the active epoch's controller** (`src/skills/agent-messaging/src/agent-messaging.ts:703`)
  - Issue: `delivery register` recomputes ownership from the lease/inventory at call time and immediately installs or delegates from that result, but never reads the active activation or requires its immutable `controller` to match. If a lease arms between standalone enable and register, registration delegates while the observer hook stays inert for the standalone epoch. If a composed lease becomes inactive between enable and register, registration installs a standalone hook that stays inert for the observer-owned epoch. Both races silently produce a mismatched/non-functional route and contradict the no-implicit-controller-switch contract (`plan.md:579-595`). Existing coverage exercises a stable enable-then-register state only.
  - Fix: resolve the current activation during registration, require it to be active for the exact collaboration/session/worktree, pass its controller as the requested controller to ownership assessment, and fail closed if live ownership no longer supports that same controller. Add both lease-arm and lease-disarm races between enable and register.
  - Requirement: p03-t02 immutable controller binding, single route, and registration update.

The user guide correctly says no live probe ran. In a release-facing summary, the unqualified wording can be read as a provider acceptance claim.
  - Fix: say “fixture-tested composition-capable Codex Stop owner” (or equivalent) and retain the explicit live-unverified boundary.
