## Considered and rejected

- **Panel deliberation flow** — `consensus-panel` is explicitly single-round and independent; panelists never debate, vote, or converge (`user-guide/consensus/panel.md:110-117`). A fan-out/fan-in picture would be one box per panelist and nothing else.
- **Phone-a-friend 7-step workflow** — linear numbered steps with one approval gate (`user-guide/consensus/phone-a-friend.md:18-31`); the prose already reads as the diagram, and positioning is covered by planned diagram #3.
- **Evaluate guided rubric creation** — elicit → adapt example → write draft → invoke with `--rubric` is a single linear path (`user-guide/consensus/evaluate.md:52-71`); the only real mechanism is the first-12-criteria cap, which is a sentence.
- **Standalone-vs-plugin install matrix** — genuinely a matrix of host × form (`user-guide/installation.md:26-132`); a flowchart would restate two existing tables and add the duplicate-entry warning as a node.
- **Cursor independent status facets** — six facets that deliberately do *not* compose into one health inference (`cursor-collaboration-reliability.md:166-182`). That is an anti-relationship; a diagram would invent edges the design forbids.
- **Repository layout as a layered tree** — authored vs generated vs provider-view vs local-only (`engineering/repository-layout.md:12-43`) is worth a picture, but it overlaps planned diagram #1 (one skill → many installation forms) heavily enough that it should be folded into #1 as an extra "provider views / local-only" band rather than drawn twice.
- **Docs navigation contract** — `## Contents` + `meta.json` + generated inventory (`contributing/documentation/authoring.md:12-50`) is a set of rules, not a mechanism with branches.

## Summary of the top five

Five diagrams would do the most for readers. **(1) Verdict capture** is the biggest gap: nothing
shows that a verdict arrives either through a `consensus submit` sidecar or a parsed final message,
with schema-validation retries and a success-exit-code-with-failure envelope — one sequence diagram
explains most of the diagnostics vocabulary. **(2) Verdict precedence** draws the ordering the code
calls mandated but the docs never show: impasse short-circuits, convergence next, escalation only
after convergence is declined. **(3) Resume derived from the record stream** explains why resume is
safe and re-runs only the synthesis call. **(4) The collaboration lease state machine** corrects the
likeliest reader error — treating a timed-out `idle` lease as an active waiter. **(5) Cursor's
delivery pointer vs continuity checkpoint** is the hardest idea here and exists only as dense prose.
Note four of the brief's "likely rich areas" are already diagrammed; remaining value is a layer
deeper.
