Original request

Past coding-agent sessions were hard to find again. The user wanted a repeatable skill in the ~/code/skills repository that lets any agent locate an earlier session from a fuzzy description, using the repository's existing notes on session schemas and store locations to keep searches fast.

What triggered the project
Source sectionWhat it records
Overview On 2026-09-29 the user could not place a “Perceive Now” discussion among Claude Code, Codex, Cursor, or two machines. An ad-hoc grep over about 12 GB ran for more than 5 minutes without finishing.
Initial Request Requirements were settled in a brainstorm that ran from 2026-09-29 to 2026-10-01, then handed to an autonomous quick-mode run.

The discussion turned out to be a ChatGPT thread. It surfaced only because one Codex session happened to capture ChatGPT thread titles in its tool output. That near-miss shaped several later choices.

Success criteria

  • An agent in Claude Code, Codex, or Cursor gets a ranked list containing the target session from a fuzzy description plus optional time or repo hints.
  • History and metadata lookups return in seconds; full-content scans honor time windows and line-length caps.
  • A repo hint that misses widens the search and says so.
  • Tool output stays out of results until the last, deepest search step.
  • Subagent transcripts do not flood results; archived Codex sessions are found and labeled.
  • When nothing is found, the skill asks about ChatGPT and about other machines.
  • Vitest coverage, repository build and drift checks, a user-guide page, and a fix for the stale export-transcript path.

Constraints and exclusions

  • Read-only over session stores, with no user-specific hosts, paths, or names shipped.
  • A dependency-free bundled Node CLI; rg and sqlite3 are optional speed-ups.
  • Short, redacted snippets only, because transcripts can hold secrets.
  • Graceful handling when internal store schemas drift.
  • Out of scope: a ChatGPT adapter, the Cursor SQLite chat store, persistent indexes, semantic search, session summarization, and automatic multi-machine fan-out.

Key agent decisions

Seven choices shaped what shipped. Each card pairs the decision with its reason and what it changed.

Stateless, tiered search

Why: a persistent full-text index needs upkeep and would create a new store that can hold secrets.

Effect: the CLI keeps no cache. Speed comes from trying cheap tiers first, time windows, cwd hints, and skipping noisy records.

Optional rg prefilter, Node verifies

Why: rg and sqlite3 may be missing on some hosts.

Effect: rg -l only narrows candidate files and Node classifies every hit, so results match with or without rg.

Repo hints widen, never filter

Why: a wrong hint should not turn into a false “not found”.

Effect: a --cwd hint is searched first, and an empty result reruns everywhere with widened: true.

Adapters own record classification

Why: the shared transcript normalizers truncate or drop text that search needs.

Effect: each runtime adapter extracts and classifies its own records while still reusing the shared parser.

Tool output only on the deep step

Why: routine results should show what people and agents wrote, yet cases like the ChatGPT titles must stay reachable.

Effect: tool output is searched on the final deep step or with --include-tools; that step always bypasses the prefilter.

Redact snippets at scan time

Why: keeping full hit text until ranking let memory balloon on broad queries.

Effect: each hit holds a short, already redacted snippet. Peak memory dropped sharply; broad queries got slower.

Local-only, with opt-in remote recipe

Why: the shipped skill must stay machine-agnostic and never embed hostnames.

Effect: the CLI searches only the local machine. To reach another machine, the agent runs a documented, injection-safe ssh recipe on a host the user names, which also copes with remote shells that lack Homebrew on PATH.

As-built architecture

The skill ships two ways from one canonical source under src/skills/session-search/: standalone as skills/session-search and as session:search in the session plugin. The agent follows the SKILL.md guidance and calls a bundled CLI that reads local stores and writes only to stdout and stderr.

Search tiers, cheapest first

  1. History: the Claude and Codex prompt history files.
  2. Metadata: Codex threads via a read-only, schema-probed sqlite3, the Codex session index, and Claude titles.
  3. Content: a bounded scan of user and assistant text, optionally narrowed by rg -l.
  4. Deep: adds tool output, including Codex MCP results that live only in item_completed items.

Ranking and safety

  • Ranking favors more distinct patterns, user-typed hits, title or first-prompt hits, cwd matches, and recency.
  • Subagent and Codex-child hits roll up to their parent session.
  • Redaction masks credential families, URL userinfo, auth headers, and multi-level escaped JSON.
  • A large-scan guard asks before huge scans; --deadline-ms bounds the run, including rg.
  • A missing table, locked database, or absent sqlite3 marks the metadata tier degraded instead of crashing.

Where the build departed from the design

  • Real Codex stores keep MCP results only in item_completed items, so extraction grew to cover them (p03-t04).
  • The deep step runs only when the content tier is selected, and the reported tier list names only scans that ran (p02-t06).
  • A single snippetFor helper redacts and then windows text, replacing a two-step composition.
  • Redaction covers more token families than designed, plus URL userinfo, auth headers, and escaped JSON.
  • Hits keep a bounded snippet and a sequence number instead of full text (p05-t03).
  • The design was realigned to the shipped code at every review; the code is the source of truth.

Outcome

Any coding agent can now find a past local session from a fuzzy description. The original motivating Codex rollout is findable on the deep step, and results were identical before and after the final revision.

What now works

  • /session-search standalone and session:search in the plugin, routed from requests like “find the session where we…”.
  • Ranked, redacted results across Claude Code, Codex, and Cursor stores.
  • Automatic widening from a repo hint, large-scan confirmation, and deadline control.
  • An opt-in recipe for searching another machine the user names.
  • Docs, including a user-guide page and the corrected Codex transcript path.

Review follow-ups in the backlog

None of these are regressions. Affected sessions stay findable through other tiers or content.

  • Exit-gate L1: a custom title in the bounded prefix can lose to a generated title in the tail. Only title-tier ranking is affected.
  • Exit-gate L2: Codex sessions that exist only as metadata lose their archived, child, and title labels when the rollout file was pruned.
  • Exit-gate L3: the remote history fallback excerpt can drop the match and session id, only on hosts without the skill installed.
  • Final cycle-four Low: Claude-only slug and sessionId keys are blanked on Codex lines. This predates p05-t06 and touches 12 local lines, mostly Stoa memory slugs.
  • Final cycle-five Low: a very long cwd on an oversize old-key-order Claude tool line can yield a path-only deep hit.
