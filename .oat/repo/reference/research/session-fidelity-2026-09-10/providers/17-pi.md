## Storage surfaces and identity

ccrider discovers Pi sessions under `~/.pi/agent/sessions/`. The inspected file parser recognizes a `session` header with id/cwd and `message` records with a nested message payload. Its selected native resume command is `pi --session <id>`; fork uses `pi --fork <id>`.

This guide documents only the subset read by that importer. The four requested repos do not, through that code path, establish a complete Pi branching, compaction, or tool-call schema.

## Field dictionary

The tables enumerate the fields modeled in this packet. A listed field is optional unless the linked JSON Schema requires it for that specific carrier. Optional does not mean unimportant: preserve it when present. Unknown fields and unrecognized record variants must remain available for later inspection.

### Pi: ccrider-observed session/message JSONL subset

[JSON Schema](../schemas/native/pi-record.schema.json) · [Synthetic example](../examples/native/pi-record.json)

| Field | Type | Information carried |
|---|---|---|
| `type` | string | session header or message in the inspected importer; other native variants are not modeled. |
| `id` | string | Session ID on header; event ID on message record. |
| `timestamp` | string | Recorded timestamp string; preserve original representation, parse only when valid. |
| `cwd` | string | Working directory from session header. |
| `message` | object | Structured carrier; see nested fields. |
| `message.role` | string | user, assistant, or toolResult are recognized by the importer. |
| `message.content` | string / array | Text content where accepted by shared text decoder. |
| `message.content[].type` | string | Content variant; only text is indexed by this importer. |
| `message.content[].text` | string | Text content. |
| `message.provider` | string | Recorded model provider. |
| `message.model` | string | Recorded model. |
| `message.timestamp` | number | Numeric timestamp interpreted as milliseconds since Unix epoch by the inspected reader. |

## Ordering, correlation, and interpretation

The header id is session identity; message-record id is event identity. ccrider derives stable import UUIDs from file stem and event ID or a sequence fallback. Its normalized sequence counts selected messages, not every physical native record.

It accepts user, assistant, and toolResult roles. Only text content is extracted into searchable history, with the raw inner message retained for selected text-bearing records. A line timestamp is preferred, then numeric payload.timestamp interpreted as milliseconds, then file mtime. A fallback time is not a measured event time.

## Fidelity of the inspected tools

Assistant tool-only records can be dropped when they contain no text. ToolResult text can be indexed without retaining a complete normalized call/result relationship in the public MCP message shape. Unknown record types are not part of the imported conversation. Therefore neither the importer nor this partial schema proves native Pi lacks richer tool or tree data.

## Reuse implications for your scripts

Use ccrider for discovery/search/resume, and capture a representative native Pi session before adding a high-fidelity adapter. Preserve ignored payloads and parent/branch fields if present, but do not assign semantics without evidence. Pi is included because it is in the repository coverage union, not because complete Pi tool extraction has already been established.
