# Import a seed before a native fork

Accepted implementation design, 2026-09-30. Second Opus review passed with low-severity clarifications incorporated; disposition is recorded in [design review notes](design-review.md). Implements [BL-260930-import-sessions-before-native](../../../pjm/backlog/archived/BL-260930-import-sessions-before-native.md). Opus high design review through consensus precedes GPT-6.1 Sol implementation. This document authorizes no provider execution.

## Interface and outcome

Preserve `discover`, sanitized `preview`, and same-provider `prepare`. Add one `import` command to the existing generated entrypoint:

```text
import --source PATH --target PATH --session PROVIDER:cli:UUID
       --to codex|claude --entry-point source-other|destination-fresh
       [--target-home PATH] [--json]
       [--apply --expect-plan SHA256]
```

First-release cross-provider import requires a completed, inactive CLI source. `source-current` refuses with `source-current-import-unsupported`: finish the source turn, exit that source session, then invoke from the destination or another session. Do not implement live-prefix cutting. Existing same-provider `source-current` guidance is unchanged. Source and destination must remain distinct registered worktrees of the same repository.

Default is read-only planning. Reject same-provider import, Cursor, arbitrary transcript paths, unknown flags, and `--apply` without its digest. The skill workflow obtains the user's cross-provider intent, presents the plan's conversion/privacy limits, then applies within that authorization. Planning creates no files. Applying creates only the target-native seed transcript; output says **seed imported; native fork not created** and supplies the caller-run command.

Public API: `planSessionImport(input)` returns a versioned public plan; `applySessionImport(input, expectedDigest)` independently recomputes it. Plans include qualified source, source-byte SHA-256, canonical worktrees/home, Git evidence, converter revision, seed ID/path, counts, omissions, destination occupancy, and digest. They exclude conversation text and raw tool payloads. Digest UTF-8 canonical JSON with recursively sorted object keys and integer-only numeric plan fields, including every behavior-affecting field and expected encoded transcript hash. Occupancy is displayed but excluded from the digest; apply independently checks it. Source, Git, home, routing, or omission changes require a new plan; no automatic retry. Reapplying the original digest to exact existing bytes returns `already-imported`.

## Qualification and conversion

Reuse exact selection in `guidance-discovery.ts:332-361`, source-path resolution from `guidance-cli.ts:252-345`, and same-repository registered-worktree checks in `git-target.ts:260-333`. Refuse dirty source; report destination dirt. Canonicalize through `realpath` once and use that destination everywhere. Revalidate immediately before publication. Adapt raw-path resolution to return import-specific errors instead of `preview-incomplete`. Current discovery's conventional source-home and exact-cwd limitations remain (source lookup does not honor alternate provider-home environment variables); do not expand shared discovery in this change.

Read selected raw JSONL with a new strict, bounded snapshot reader: fatal UTF-8 decoding, object-only records, no skipped malformed/partial lines, identity corroboration, stable inode/size/mtime and byte digest before publication. Limits apply to raw bytes before media replacement: 32 MiB source/output, 100,000 records, 4 MiB per line, 30-second operation deadline; fail rather than truncate. Reject source symlinks, missing/ambiguous identity, contradictory owning identities, malformed native fields, unsupported rollback, and unreadable stores. Use a distinct `import-limit-exceeded` refusal for any bound. No process-stopping or lock inference; users stop writers and replan if the snapshot changes.

Use a small private union for ordered user/assistant text, completed function/custom calls, and matching results. Preserve text, call IDs/names, function JSON-object arguments, raw custom input, string/text-array outputs, and supported assistant phases. Claude custom-input projection uses `{input: raw}`; namespace and phase distinctions unavailable in Claude are counted omissions. No round-trip metadata framework. Unsupported argument shapes fail.

Claude owning identity must match the selected filename UUID and active leaf sessionId/cwd. The pinned experiment rewrote all copied rows to the child sessionId; do not assume mixed IDs are always normal. Ancestor IDs may differ only on the validated active parent chain; record this inherited provenance, never use it to select another owner. Queued Claude input is refused with `unsupported-queued-input` anywhere in the selected transcript until delivery ordering is supported; all other attachment records also refuse until a safe projection is supported, instead of being classified as metadata. Claude reader follows the last main conversation leaf's parent chain through non-message nodes, excluding sidechains/abandoned branches. Reject duplicate IDs, cycles and missing parents. Recover only pure parallel-result sibling records explicitly linked to active call nodes; never recover sibling user text. Stop at a compaction boundary with a surviving-context notice.

Codex reader uses the first `session_meta` as owning identity; inherited later headers are provenance, not ownership. Qualified owning cwd must match source; inherited cwd cannot override it. `compacted.replacement_history` replaces accumulated history; missing/invalid replacement history fails with `unsupported-codex-compaction`. Summary-only local compaction is a documented first-release refusal, not reconstructed heuristically. Reject `thread_rolled_back` as `unsupported-rollback`. Track known `task_started`, `task_complete` and `turn_aborted` lifecycle outcomes; trailing pending/error/aborted state after retained content refuses completion. Later retained conversation or valid replacement history supersedes historical lifecycle failures. Other `event_msg` display subtypes are not conversation. `turn_context` is metadata and never overrides owning cwd, even when it differs; count omitted runtime context. Unknown top-level or response-item types refuse. Within replacement history, unknown/opaque non-message/non-tool items (other than recognized reasoning) refuse `unsupported-codex-compaction`. Read native `response_item` messages and function/custom calls/results directly.

Validate unique calls, exactly one matching result of the correct kind, and completion. Reject pending, orphan, duplicate and interleaved tool exchanges. For Claude output, group parallel assistant calls together and require their entire result group immediately afterward; never let the loader fabricate interruption results. Require the portable history to end with nonempty assistant text after all tools resolve; final Codex commentary and Claude synthetic/API-error assistant rows cannot establish completion; validate the Claude row supplying final retained assistant text even if omitted context follows; otherwise `incomplete-source-turn`. Incomplete-turn and pending-call errors include the finish/exit-source and invoke-elsewhere remedy even if the caller mislabeled the entry point. Emit no Codex function-call item `id` that could require omitted reasoning. Validate tool IDs against a conservative importer profile (1–128 ASCII letters/digits/underscore/hyphen) and tool names against `^[A-Za-z0-9_-]{1,128}$`; incompatible values refuse, never silently rename. The name constraint is documented by [Anthropic](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools); the ID profile is our conservative supported subset, not a claimed API limit. Codex namespaces are separate fields and may be omitted with a count; dotted literal names refuse for Claude.

Omit private reasoning, system/developer instructions, permissions, credentials/configuration fields and source runtime envelopes. Classify provider-injected user-role context before conversion using an explicit allowlist, with counted omissions: Codex leading whole-message AGENTS instructions and runtime XML envelopes (`environment_context`, `permissions`, `user_instructions`, `apps_instructions`, `skill`, `stoa-profile`), and Claude `isMeta` records plus fully recognized local-caveat/system-reminder envelopes and command display wrappers (preserve safely delimited command arguments as user text). Wrapper recognition requires the expected complete shape, not substring matching or arbitrary XML. Omit a standalone known envelope; when a known prefix can be safely delimited from trailing user text, retain the trailing text; ambiguous mixtures refuse `ambiguous-runtime-context`. Strip the fully recognized leading Codex ambient-browser wrapper and count it. Preserve ordinary user text, quoted wrapper examples, and tool payload text; do not scrub tool results using broad XML regexes. Recognition is shape-based and cannot distinguish a deliberately pasted identical whole-message envelope. Unknown active/control types refuse; known off-chain metadata uses a small explicit allowlist. Do not claim universal removal of injected instructions. Recognized image/audio/media blocks become visible placeholders and omission counts, without URLs, file access or embedded bytes. Unknown conversational/control/tool structures fail closed. Report surviving compaction context and synthetic assistant-first preface explicitly.

Import preserves raw supported text/tool payloads, unlike sanitized previews; these may contain secrets. Explain that distinction before apply. Metadata omission is not secret detection or redaction.

## Storage, identity and commands

Resolve destination home from explicit `--target-home`, otherwise target `CODEX_HOME`/`CLAUDE_CONFIG_DIR`, otherwise the conventional user directory. Require an existing home and reject invalid/empty routing. Track home source (`default`, `environment`, `explicit`) and both routing spelling and canonical storage realpath. Resolve relative supplied spelling to an absolute path without changing symlink spelling; use realpath only for containment/identity. Refuse target homes within either selected worktree before writes (`target-home-within-worktree`), because publication would invalidate its own reviewed Git evidence. Create only required store descendants. Never copy configuration or register desktop projects.

For Claude, use the private project-key function `canonicalCwd.replace(/[^A-Za-z0-9]/g, "-")`, matching the pinned Teleporter encoder. Refuse encoded keys longer than 200 characters instead of guessing unproven client long-path hashing. Real-client acceptance must cover spaces and underscores. Do not change shared discovery encoding in this feature.

Derive a deterministic UUID v8 with RFC variant/version bits from SHA-256 of converter revision, source provider/native ID/byte digest, target provider and canonical destination/home. Stable source timestamp supplies deterministic Codex date/path. Same snapshot repeats the same ID; changed source or converter produces a new reviewed seed, preserving older imports.

Embed minimal versioned provenance under the extra `session_import` key in the owning Codex `session_meta.payload`/first Claude row (never overwrite typed native enum fields): source provider/ID/digest, converter revision and omission counts. It declares a reconstructed import, never source-native `forked_from_id`. Codex emits native response items plus tested generic `imported_history` display events; Claude emits linked native message/block envelopes. Historical tool names do not register or authorize tools. Encode error results visibly where Codex lacks Claude's native error bit.

No-follow checks inspect the exact target path, matching UUID-suffix Codex files in the deterministic date directory and archived store. Bounded directory enumeration (50,000 entries, deadline above) fails if incomplete. Claude checks its exact project path; no whole-home scan. An exact existing seed is reused without writing. Any appended/evolved/truncated/modified seed refuses `seed-diverged`; advise manually forking that existing seed if its extra history is wanted. An archived match refuses `seed-archived`; advise restoring through the provider's supported archive workflow and replanning. No reimport nonce, resurrection, or overwrite in this version.

Publication uses one file: stage a dot-prefixed name with a non-JSONL suffix using exclusive creation and mode `0600` in the final parent, flush/fsync, then `link` atomically without clobbering; fsync the parent directory and remove only the owned temporary name. Empty store directories may remain after a failed apply; cleanup errors are secondary to the original refusal when both occur. Report post-publication durability/cleanup failures honestly; an exact seed remains safe to retry. Unsupported hard links fail, with no overwrite fallback. Store descendants must be directories without symlinks; recheck containment and parent identities immediately before linking. Canonical home aliases are allowed only at root resolution. This assumes the user-owned home is not adversarially renamed concurrently; Node path APIs cannot guarantee containment against that attack. Fail on detected drift. No sidecars, cleanup of imports, or multi-file transaction.

Reuse `guidance.ts:77-107` quoting/physical-cwd guard, with a separately shell-quoted validated env argv prefix. For an explicit or environment-selected home preserve its routing spelling:

```text
env CODEX_HOME=HOME codex fork SEED
env CLAUDE_CONFIG_DIR=HOME claude --resume SEED --fork-session
```

For the conventional default, emit no assignment and guard that the relevant variable remains unset (empty was rejected when planning). Thus the command preserves default-provider configuration behavior and refuses a changed routing environment. Catch store EPERM/EACCES as `store-write-denied`; print the exact same import/apply/digest command for the user to run in a terminal, with no automatic privilege escalation or retry. An environment-selected home must also prefix this terminal replay with the original quoted variable assignment so the same routing source is recomputed.

Require exit from a fresh provider session when necessary. Never run either command, return a guessed child ID, or claim sidebar placement.
