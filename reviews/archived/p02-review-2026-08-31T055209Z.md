That locally contradictory receipt could reach the later contract-activation review as machine-valid.
  - Fix: For `status: passed`, reject any receipt whose observed child equals the parent; Claude's existing requested/observed equality then also guarantees its requested child differs from the parent. Add negative passed-receipt fixtures for both providers.

### Medium

- **Aggregate preview work can cross its hard byte/record cap before detection** (`src/transcript/coding-session-handoff/preview.ts:239`)
  - Issue: The fix now debits trustworthy `bytesRead` and `recordsInspected`, so an over-limit batch no longer returns success. However, each complete 2 MiB/10,000-retained-record tail read finishes before the aggregate check at lines 260-266. The real tail reader may inspect substantially more than 10,000 records, so a request can perform more than 32 MiB or 100,000 record inspections before failing, contrary to the design's before/during-read hard-bound rule.
  - Fix: Give the tail reader a shared remaining byte/inspected-record budget (separate from the retained-record limit), consume it during the read/parse loop, and surface the matching aggregate failure immediately. Add real-reader tests proving the counters never exceed either aggregate limit, including the crossing file.
  - Requirement: FR2, NFR5; p02-t03

- **Candidate and preview ordering remains host-locale dependent** (`src/transcript/coding-session-handoff/discovery.ts:223`)
  - Issue: Discovery still uses argument-less `localeCompare`, as does preview at `src/transcript/coding-session-handoff/preview.ts:219`. The ordering of accepted mixed-case, punctuation, or non-ASCII native IDs can vary with the host ICU locale despite FR1/NFR5 requiring deterministic provider/native-ID order.
  - Fix: Use one shared locale-independent code-unit or bytewise qualified-ID comparator and cover mixed-case, punctuation, and non-ASCII IDs in discovery and preview tests.
  - Requirement: FR1, NFR5

- **Multiline preview output still cannot pass its own runtime schema** (`src/transcript/coding-session-handoff/types.ts:570`)
  - Issue: `parsePreviewEntry` uses the general control-free `string()` validator, which rejects newline and tab. The preview producer preserves ordinary sanitized multiline message text, so a valid produced preview fails `parseSessionPreview`; a direct post-image check rejects it as `preview-entry-text`.
  - Fix: Add a preview-text validator that permits intended whitespace such as newline (and tab if supported) while rejecting NUL and unsafe terminal controls, then add a producer-to-parser multiline round-trip test.
  - Requirement: FR2; p02-t01, p02-t03
