- **Guidance discovery is still non-functional on realistic transcript stores; the `prev1-t07` fix does not satisfy R1/R2 in practice**
  (`src/transcript/coding-session-handoff/guidance-discovery.ts:167`,
  `src/transcript/coding-session-handoff/guidance-discovery.ts:152`,
  `src/transcript/session-observer/lib/locate.ts:496`,
  `src/transcript/core/runtimes.ts:910`,
  `src/transcript/core/runtimes.ts:859`,
  `src/transcript/coding-session-handoff/guidance-cli.ts:272`,
  `src/transcript/coding-session-handoff/guidance-cli.ts:325`)
  - Issue: Independent read-only verification at HEAD on this machine (shipped bundle,
    `persistence: forbid`, no provider executed, only codes and counts retained):
    `discover --source <this worktree> --provider all|claude|codex|cursor --json` all
    still return `discovery-incomplete`, exactly as before `prev1-t07`. Three
    mechanisms survive, each verified against the code and the real store:
    1. **Projection-layer abort on stale recorded cwd.** After the locator returns,
       `discoverGuidance` canonicalizes every transcript's `recordedCwd` and throws
       `discovery-incomplete` for the whole provider when `realpath` fails
       (`guidance-discovery.ts:167-171`). Any unrelated transcript whose worktree has
       since been deleted therefore erases the provider — the same failure class I1
       named, one layer up. Here 11 of the 29 Claude transcripts that survive the
       locator have a recorded cwd that no longer exists, so `--provider claude` fails
       before any source candidate can be returned. Deleted worktrees are the norm for
       this product's target user.
    2. **Over-broad "unattributable" classification.** `readMetadataRecordsBounded`
       reports `incomplete: true` whenever the file is larger than the 256 KiB window
       (`runtimes.ts:910`, `window.fileSize > window.buffer.length`) or has more than
       128 records (`runtimes.ts:859-861`), and `candidateDerivedFieldsBounded` treats
       any `incomplete` read as unattributable (`locate.ts:496-503`) before it ever
       looks at the extracted cwd. Measured with the generated reader over the full
       Claude store: 137 of 168 transcripts exceed 256 KiB, all 137 are flagged
       incomplete, and all 137 have a `cwd` record inside the bounded prefix. Under
       `summarize` they are silently omitted and reported as `oversized-record`
       (the trailing window-cut fragment triggers that diagnostic), which is not a
       stable, truthful reason for a well-formed transcript. Real coding sessions
       are almost always larger than 256 KiB, so the "fully attributed source
       candidates" R2 promises to retain are precisely the ones dropped. This also
       shows the deferred p02 M1 ("exactly 128 records are falsely incomplete") is
       not a narrow edge but the common case.
    3. **`preview` and `prepare` cannot be narrowed.** Both call
       `discoverGuidanceCandidates(source)` with no provider filter
       (`guidance-cli.ts:272`, `:325`), so the documented Cursor fail-closed result
       and any Codex aggregate-budget failure (`--provider codex` fails here with
       `DISCOVERY_BYTE_BUDGET_EXCEEDED`, see M1) make preview/prepare fail even for a
       `claude:cli:…` key the user found with `--provider claude`. `SKILL.md:40-41`
       still instructs `--provider all` as the first step while `SKILL.md:22-25`
       states a matching Cursor store returns `discovery-incomplete`.
    The regression fixtures added in `prev1-t07` use tiny synthetic target transcripts
    (`tests/session-observer/locate.test.ts:647-683`, `:942-977`), so they cannot
    fail on any of the three mechanisms; the projection test mocks `discover`
    (`tests/coding-session-handoff/guidance-discovery.test.ts:226-256`).
  - Fix: Keep the `summarize` seam and strict defaults, and close the three gaps
    together with a single artifact alignment:
    (a) In `candidateDerivedFieldsBounded`, decide attributability from the extracted
    evidence, not the window flag: when `meta` and `recordedCwd` were both extracted
    from the bounded prefix, return the derived fields even if `read.incomplete` is
    true because of file size or record count; reserve `unattributable` for genuine
    `malformed-record`/`read-failed`/`cwd-missing`/no-metadata cases, and stop
    reporting a window cut as `oversized-record`. Re-disposition p02 M1 in the same
    change (it is this mechanism).
    (b) In `discoverGuidance`, under the guidance policy count a non-canonicalizable
    `recordedCwd` as a path-free `cwd-unresolvable` summary entry and `continue`
    instead of throwing for the provider; keep the throw for the strict path and for
    the source's own candidates if desired.
    (c) In `defaultPreview` and the `prepare` dependency, pass
    `providers: [provider parsed from the session key]` so a Claude/Codex key is not
    blocked by Cursor or the other provider; update `SKILL.md` step 2 to recommend
    `--provider claude|codex` (or explain when `all` is expected to fail).
    (d) Add filesystem fixtures that would have caught this: a target transcript
    larger than 256 KiB and longer than 128 records with `cwd` in the prefix, an
    unrelated transcript whose recorded cwd directory does not exist, and a CLI-level
    `preview`/`prepare` test where the Cursor provider throws; assert the source
    candidate is returned and preview/prepare succeed.
    (e) Align `design.md:29-34` and `spec.md` R2 wording with the corrected
    definition of "unattributable" so the artifact matches behavior.
  - Requirement: R1, R2, R7

  - Issue: `discoverCodex` consumes `fileStat.size` for every session file with the
    recency cutoff disabled, against a 512 MiB aggregate cap, although the bounded
    reader reads at most 256 KiB per file. This machine's Codex store is 7.2 GB across
    2,527 sessions, so `--provider codex` throws `DISCOVERY_BYTE_BUDGET_EXCEEDED`
    after ~190 ms and the guidance projection reports `discovery-incomplete`. The
    accepted R2/design text ("aggregate-budget … failures remain incomplete",
    `design.md:239-241`) makes this conforming, but the conforming behavior is that a
    few months of Codex use disables Codex discovery entirely. This is artifact
    alignment as much as code: either the budget should measure what is actually read
    (bytes consumed by the bounded prefix reads, or `min(size, maxMetadataBytesPerEntry)`
    per entry) or the spec/docs must state the store-size ceiling plainly.
  - Fix: Charge the exact-all budget with the bytes the bounded reader actually
    consumes (or `min(size, 256 KiB)` per entry) so the 512 MiB cap bounds I/O rather
    than store size; add a fixture with many small-header, large-body Codex files
    whose stat total exceeds the cap but whose bounded reads do not. If the stat-size
    semantics are deliberately kept, update `design.md:239`, `spec.md` R2, and the
    docs "Current limitations" list to say Codex stores above 512 MiB cannot be
    discovered, and have the failure envelope say so (see M2).
  - Requirement: R2, R7

- **`discovery-incomplete` failure envelope drops the failing provider and locator reason**
  (`src/transcript/coding-session-handoff/guidance-cli.ts:152`,
  `src/transcript/coding-session-handoff/guidance-cli.ts:219`,
  `src/transcript/coding-session-handoff/guidance-discovery.ts:73`)
  - Issue: `GuidanceDiscoveryError` carries `provider`, and the locator throws stable
    `SessionDiscoveryError` codes (`DISCOVERY_BYTE_BUDGET_EXCEEDED`,
    `DISCOVERY_TRANSCRIPT_INCOMPLETE`, …), but `discoverGuidance` discards the cause
    (`catch { throw new GuidanceDiscoveryError('discovery-incomplete', provider) }`)
    and `errorCode` renders only the outer code. With `--provider all` the user sees
    `{"code":"discovery-incomplete"}` and cannot tell whether Cursor's designed
    refusal, a Codex budget overflow, or a stale Claude cwd caused it, nor which
    `--provider` value would work. The unattributable summary is only emitted on
    success. Provider name and stable reason code are path-free and safe to expose.
  - Fix: Attach `provider` and a stable `reason` (the locator code or the projection
    reason) to the failure envelope's `error` object; add a CLI test asserting the
    fields are present and contain no path or session ID.
  - Requirement: R2, R7

which is true for essentially every real transcript. The stale-cwd abort and the
un-narrowable preview/prepare are integration gaps the narrowed fixture set did not
