### Important

- **Discovery modes share incompatible classification-cache entries** (`src/transcript/session-observer/lib/locate.ts:455`)
  - Issue: `candidateDerivedFieldsBounded` accepts any cache hit keyed only by path, mtime, and size, regardless of whether it came from an ordinary whole-file read or the new bounded metadata-prefix policy. It also stores its prefix-only classification back into that same cache at line 486. This breaks both directions of the additive contract: after ordinary discovery primes an oversized transcript, an `exact-all` call with a 64-byte per-entry cap succeeds instead of raising `DISCOVERY_TRANSCRIPT_INCOMPLETE`; after `exact-all` primes a transcript whose real conversation begins after record 128, ordinary discovery reports `unengaged`/zero real messages while a fresh ordinary cache reports `engaged`/two messages. The first direction bypasses the fail-closed bounded seam and the second silently changes legacy observer behavior.
  - Fix: Namespace cache entries by derivation policy and effective bounds, or keep bounded request-local results in a separate cache that ordinary discovery cannot read. Exact-all discovery must not consume entries produced by an unbounded/default read, and default discovery must not consume prefix-only classifications. Add regression tests for both default-to-exact-all and exact-all-to-default transitions using one shared `ClassificationCache`.
  - Requirement: FR1, NFR1

- **The entry budget counts JSONL candidates, not the entries traversed** (`src/transcript/session-observer/lib/locate.ts:840`)
  - Issue: Codex recursion materializes every directory with `readdir` and calls `consumeEntry()` only after an entry is already known to be a JSONL file (lines 848-855). Claude likewise materializes and filters directory arrays before counting only retained JSONL files (lines 642-649 and 713-742). A reproduced scan configured with `maxEntries: 1`, 25 non-JSONL entries, and one transcript succeeds, so the declared work bound does not limit traversal or `readdir`'s up-front memory. The deadline check after enumeration cannot bound a single large directory read. This leaves the p01-t02/NFR5 entry limit ineffective for directory-heavy or adversarial stores.
  - Fix: Stream directories with `opendir` (or another bounded iterator), consume the entry budget for every directory entry visited before filtering or recursion, and apply the same rule to both Codex and Claude enumeration. Add fixtures where non-JSONL files and nested directories alone cross `maxEntries`, and assert all-or-error rejection with no candidate result.
  - Requirement: NFR5, FR1
