### Important

- **I1 — Codex cleanup accepts an unvalidated option-shaped machine ID as exact** (`src/transcript/coding-session-handoff/behavior-gate.ts:371`)
  - Issue: `observedId` accepts every nonempty `thread_id`/`session_id` string (`behavior-gate.ts:400-408`) and the gate stores that value as the child ID (`behavior-gate.ts:674-687`). Cleanup then calls any nonempty value an exact ID and constructs `['delete', '--force', id]` without applying the native-ID validation already used by invocation building (`behavior-gate.ts:1068-1096`; `behavior-contracts.ts:194-197`). The design defines Codex cleanup as `codex delete --force <UUID>` (`design.md:453-454`), yet a machine-emitted `--help` is treated as a complete cleanup ID. It is passed as a CLI option rather than a proven session operand; if that command exits successfully, the receipt reports provider cleanup `removed` even though the intended child deletion was not established. This violates p03-t08's complete-exact-ID condition and the fail-closed untrusted-ID boundary.
  - Fix: Validate every machine-observed Codex parent/child ID before storing or using it, using the exact Codex 0.151.0 UUID grammar (and at minimum the existing native-ID control/leading-hyphen checks). Treat invalid values as missing, delete only retained valid exact IDs, and keep cleanup `failed` for every attempted boundary without one. Add cleanup and end-to-end gate tests with leading-hyphen, non-UUID, and control-bearing IDs, including a cleanup runner that returns success, to prove the receipt cannot falsely report `removed`.
  - Requirement: p03-t08; NFR3; FR6 cleanup binding.

### Medium

- **M1 — A ready Claude plan still cannot round-trip through the plan parser** (`src/transcript/coding-session-handoff/behavior-contracts.ts:241`)
  - Issue: Claude successor argv intentionally includes an empty value after `--tools` (`behavior-contracts.ts:232-245`), while `parseNativeInvocation` applies the generic nonempty string parser to every argv element (`types.ts:361-369`, `types.ts:1016-1041`). A serialized ready Claude plan therefore fails its own schema parser.
  - Fix: Give argv elements a parser that permits the intentional empty string while retaining control-character validation, or encode the provider's no-tools form without an empty argument. Add a ready Claude plan serialize/parse round-trip test.

- **M2 — Normal planning still collapses authentication-required into probe failure** (`src/transcript/coding-session-handoff/cli.ts:546`)
  - Issue: `buildDefaultPlan` rewrites every non-authenticated probe capability to `probe-failed` with a generic `authentication` missing capability (`cli.ts:535-557`). This discards the distinct `provider-auth-required` condition and actionable login guidance represented by the provider probe contract.
  - Fix: Preserve authentication-required as a distinct deferred reason through plan/result rendering and test the normal CLI planning path for unauthenticated providers.

- **M3 — Production and read-only corroboration still compare caller path aliases rather than validated canonical roots** (`src/transcript/coding-session-handoff/cli.ts:737`)
  - Issue: production execution passes raw `source`/`target` arguments to `corroborateExact`, and read-only reconcile does the same (`cli.ts:703-738`, `cli.ts:751-763`). Corroboration requires exact raw-path equality with transcript cwd (`cli.ts:651-679`), so a valid relative or symlink alias can produce a false unresolved result even though planning already validated canonical worktree roots.
  - Fix: Carry the validated canonical roots into both corroboration paths, or canonicalize once before dispatch and reuse those roots. Add relative-path and symlink-alias tests for execute and reconcile.
