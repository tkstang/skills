## Findings

### Critical

- **Exact-all Claude discovery stops scanning after any direct slug exists** (`src/transcript/session-observer/lib/locate.ts:732`)
  - Issue: `discoverClaudeCode()` runs its all-project-directory fallback only when no encoded direct directory opened. Under the handoff's `exact-all` mode, one direct directory can therefore suppress a different Claude project directory whose transcript-record cwd canonicalizes to the same requested source. A post-image fixture with a canonical source plus a symlink alias returned only the direct-slug session and silently omitted the alias-slug session. This violates the design's requirement to enumerate every store entry within budget and makes FR1's complete exact-source candidate set false.
  - Fix: In bounded `exact-all` mode, scan every Claude project directory even after direct hits, deduplicate transcript paths, and retain entries only through exact canonical transcript-record cwd evidence. Preserve the existing direct-first short circuit for default observer discovery. Add a regression with simultaneous direct and alias/unexpected slugs and assert both exact sessions are returned while a different canonical cwd is excluded.
  - Requirement: FR1, NFR1, NFR3; p02-t02

- **A 128-record metadata prefix can hide later contradictory cwd evidence** (`src/transcript/core/runtimes.ts:815`)
  - Issue: `parseBoundedLines()` marks a prefix incomplete when it reaches `maxRecords`, but `readMetadataRecordsBounded()` returns only `parsed.records` and discards that completeness bit. The exact-all caller at `src/transcript/session-observer/lib/locate.ts:472` only sees diagnostics, and the record-cap path emits none. A 129-record post-image transcript whose first 128 records named the requested source and whose final record named another cwd was accepted as an exact candidate instead of failing path-free. That turns a bounded-read truncation into false P0 evidence.
  - Fix: Surface bounded-prefix completeness (including byte and record truncation) in the public result or emit a safe diagnostic for every incomplete condition, and make exact-all reject any incomplete metadata derivation. Add tests for a clean 129th record, a late cwd conflict, and a byte-boundary truncation; assert only stable error codes escape.
  - Requirement: FR1, NFR1, NFR3; p02-t02

### Important

- **Preview's declared input-work caps are not enforced as hard bounds** (`src/transcript/coding-session-handoff/preview.ts:239`)
  - Issue: The preview passes a 10,000 retained-record limit to the tail reader but never rejects `recordsInspected > 10,000`; the real reader can inspect more records while retaining only the newest 10,000. A 10,001-record post-image tail returned a successful bounded read with `recordsInspected: 10001`. The 32 MiB/100,000 aggregate checks also run only after each full per-transcript read, so physical work can cross the aggregate allowance before refusal. This misses FR2/NFR5's P1 hard work bounds even though returned content remains bounded.
  - Fix: Give the reader separate retained-record and inspected-record budgets, pass each request's remaining aggregate bytes/records into the next read, and stop I/O/parsing at the boundary. Reject any dependency result outside the per-transcript allowance. Add real-reader tests proving the 10,001st inspection and aggregate boundary stop work rather than merely report an overshoot.
  - Requirement: FR2, NFR5; p02-t03

### Medium

- **Candidate and preview ordering remains host-locale dependent** (`src/transcript/coding-session-handoff/discovery.ts:225`)
  - Issue: Discovery sorts qualified IDs with argument-less `localeCompare`, and preview repeats it at `src/transcript/coding-session-handoff/preview.ts:219`. The schema accepts mixed-case, punctuation, and non-ASCII native IDs whose order can vary with the host's ICU default, while FR1/NFR5 require deterministic ordering.
  - Fix: Use one shared locale-independent code-unit or bytewise qualified-ID comparator and cover mixed-case, punctuation, and non-ASCII IDs in both discovery and preview tests.
  - Requirement: FR1, NFR5

- **Multiline preview output cannot pass its own runtime schema** (`src/transcript/coding-session-handoff/types.ts:570`)
  - Issue: `parsePreviewEntry()` applies the generic control-free `string()` validator, which rejects newline and tab. The preview producer trims but otherwise preserves ordinary sanitized multiline message text at `src/transcript/coding-session-handoff/preview.ts:114`, so valid produced output fails `parseSessionPreview()` instead of round-tripping through the declared schema.
  - Fix: Add a preview-text validator that permits intended whitespace while rejecting NUL and unsafe terminal controls, then add a producer-to-parser multiline round-trip test.
  - Requirement: FR2; p02-t01, p02-t03

- **An unrelated stale worktree registration blocks valid target inspection** (`src/transcript/coding-session-handoff/git-target.ts:204`)
  - Issue: `inspectWorktree()` canonicalizes every root from `git worktree list` in one `Promise.all`. A valid requested worktree therefore fails as `not-registered-worktree` whenever any unrelated registered entry is missing/prunable. This remains fail-closed, but rejects an otherwise valid FR4 pair because of unrelated repository residue.
  - Fix: Establish registration of the requested canonical root without requiring unrelated entries to resolve. Ignore unrelated missing/prunable entries while still failing if the requested root is absent or ambiguous, and add a real-Git stale-sibling regression.
  - Requirement: FR4; p02-t04

- **The NUL-delimited worktree parser reintroduces newline ambiguity** (`src/transcript/coding-session-handoff/git-target.ts:156`)
  - Issue: Git is correctly invoked with `worktree list --porcelain -z`, but each NUL-delimited field is split again on newline. A legal worktree path containing a newline is fragmented before canonicalization, defeating the adversarial-path safety supplied by `-z` and rejecting a valid registered root.
  - Fix: Parse the `-z` porcelain grammar strictly by NUL fields without newline splitting, and audit the other Git path-returning calls for an equally unambiguous representation or direct canonical comparison. Add a real-Git fixture whose registered worktree path contains a newline.
  - Requirement: FR4, NFR3; p02-t04
