This encoding is not one-to-one: a disposable post-image reproduction showed that source roots ending in `a-b` and `a/b` share one slug, and a transcript whose own `cwd` named `a/b` was returned with `recordedCwd` rewritten to `a-b`.   - Fix: Add a strict handoff discovery path that extracts and canonicalizes exact Claude `cwd` evidence from the bounded transcript records instead of treating the project slug as exact. For a colliding directory, retain only records whose exact cwd matches the source; if a record has no trustworthy exact cwd, fail the complete provider set as `discovery-incomplete`. Add an integration fixture with two registered worktree roots whose Claude encodings collide and prove neither session leaks into the other source's result.

### Medium

- **Aggregate preview work can cross its hard byte/record cap before detection** (`src/transcript/coding-session-handoff/preview.ts:239`)
  - Issue: The corrected code now debits `bytesRead` and `recordsInspected`, so an over-limit comparison cannot return success. Each full 2 MiB tail read and its entire parse still completes before the aggregate checks at lines 260-266, however, and the real reader may inspect far more than its 10,000 retained records. Physical input work can therefore exceed 32 MiB or 100,000 record inspections before the request fails, contrary to FR2/NFR5's hard aggregate work bounds.
  - Fix: Pass the remaining aggregate byte and inspected-record allowance into each read and consume it during I/O/parsing, separately from the retained-record limit. Add real-reader crossing tests that assert work stops at the aggregate boundary rather than only reporting the overshoot afterward.

  - Fix: Use one shared locale-independent code-unit or bytewise qualified-ID comparator and cover mixed-case, punctuation, and non-ASCII IDs in both discovery and preview tests.
  - Requirement: FR1, NFR5

- **Multiline preview output cannot pass its own runtime schema** (`src/transcript/coding-session-handoff/types.ts:570`)
  - Issue: `parsePreviewEntry` applies the general control-free `string()` validator, which rejects newline and tab. The preview producer preserves ordinary sanitized multiline message text, so a valid produced preview fails `parseSessionPreview` with `preview-entry-text` instead of round-tripping through the declared JSON schema.
  - Fix: Add a preview-text validator that permits intended whitespace such as newline (and tab if supported) while rejecting NUL and unsafe terminal controls. Add a producer-to-parser multiline round-trip test.
  - Requirement: FR2; p02-t01, p02-t03

This is fail-closed, but it rejects an otherwise valid FR4 source/target pair for unrelated repository residue.
  - Fix: Establish registration of the requested canonical root without requiring every unrelated entry to resolve. Parse and ignore unrelated prunable/missing entries while still failing if the requested root itself is absent or ambiguous, and add a real-Git stale-sibling regression.
  - Requirement: FR4; p02-t04
