### Important

- **Outcome validation loses a required expected/observed divergence state** (`src/transcript/coding-session-handoff/types.ts:279`)
  - Issue: The designed `ItemOutcome` cross-discriminated union was flattened into `ItemOutcomeBase & { native: NativeOutcome; observedChildNativeId?: string }`, so TypeScript accepts combinations such as a failed native outcome with observed child evidence even though the runtime parser rejects them. In the opposite direction, the parser rejects every expected/observed child-ID mismatch for non-mapped reporting at lines 991-996. FR9 explicitly requires retaining a provider-generated expected ID and a parsed observed ID independently when corroboration fails; a different observed ID is an `unresolved`/`ambiguous` reporting outcome, not an invalid object. Rejecting it discards the exact selector evidence that read-only reconciliation and no-retry policy need.
  - Fix: Restore the design's discriminated `ItemOutcome` union so forbidden child/reporting combinations fail at compile time. In `parseItemOutcome`, require selector equality only for `mapped`; preserve both IDs for `unresolved`, `ambiguous`, or reporting `failed`. Add runtime cases for succeeded and indeterminate native outcomes with differing expected/observed IDs plus unmapped reporting, while retaining negative tests for failed-plus-child and mapped-selector mismatch.
  - Requirement: FR9; p02-t01

- **Unclassifiable discovered cwd entries are silently omitted from a supposedly complete set** (`src/transcript/coding-session-handoff/discovery.ts:131`)
  - Issue: `canonicalize(candidate.recordedCwd)` is allowed to return `null`, after which `projectCandidate` returns `null` and discovery continues as if that record were conclusively unrelated. A realpath failure or concurrent path change means exact membership could not be established; returning the remaining candidates as complete violates FR1's all-or-error boundary and allows that partial set to feed later selection. The focused tests cover an upstream `discover()` rejection and conflicting duplicates, but not failure while canonicalizing a discovered record.
  - Fix: Treat any non-null recorded cwd that cannot be canonicalized as `discovery-incomplete` for that provider, and convert invalid projected candidate fields to the same path-free failure instead of returning unchecked data. Add tests for canonicalization returning `null` and throwing after discovery has yielded a candidate; neither case may return a partial list.
  - Requirement: FR1, NFR1; p02-t02

- **Aggregate preview limits debit projections rather than actual input work** (`src/transcript/coding-session-handoff/preview.ts:238`)
  - Issue: Byte accounting uses `Math.min(candidate.size, 2 MiB)`, but `candidate.size` is discovery-time evidence and may be stale when the bounded reader stats and reads the current transcript. Record accounting at lines 256-259 counts only `read.records`, even though the tail reader may inspect and discard records beyond its 10,000-result cap. The last deadline check occurs immediately after the read at line 253, before normalization, sanitization, round grouping, and rendering. Consequently, concurrent file growth, record truncation, or slow post-read processing can exceed the 32 MiB/100,000-record/10-second batch limits while returning a successful comparison.
  - Fix: Make the bounded reader expose trustworthy per-read byte and inspected-record metrics, or pass it one shared aggregate budget that is consumed during reads. Debit those actual metrics and check the aggregate deadline after normalization/sanitization/rendering and once more before return. Add regressions for discovery-size drift, more inspected than retained records, and a clock crossing during post-read processing; every crossing must discard the complete batch.
  - Requirement: FR2, NFR5; p02-t03

- **The planned behavioral-receipt runtime schema is absent** (`src/transcript/coding-session-handoff/types.ts:163`)
  - Issue: p02-t01 explicitly requires runtime-schema fixtures and validators for receipts, but this phase defines only the `BehavioralGateReceipt` interface. A repeated absence search found no `parseBehavioralGateReceipt` (or behavior-contract parser), and `types.test.ts` has no receipt fixture. This defers a security-sensitive validation boundary into later gate code and leaves contradictory values—such as `status: passed` with failed cleanup or missing evidence—representable without one canonical exact-key parser.
  - Fix: Add canonical runtime parsers for `BehavioralGateReceipt` and `ProviderBehaviorContract`, including exact keys, provider/method agreement, digest and bound validation, verified-contract evidence requirements, and pass/cleanup cross-field rules. Add passing Codex/Claude fixtures and negative cases for unknown fields, failed cleanup on a passed receipt, missing selector/lineage evidence, malformed digests, and verified contracts without receipt provenance.
  - Requirement: FR6, NFR3; p02-t01

### Medium

- **Candidate and preview ordering depends on the host locale** (`src/transcript/coding-session-handoff/discovery.ts:205`)
  - Issue: Discovery sorts qualified IDs with argument-less `localeCompare`, and preview repeats the same pattern at `src/transcript/coding-session-handoff/preview.ts:216`. The default collation is host/ICU-locale dependent, while FR1/NFR5 require deterministic provider/native-ID ordering. IDs containing mixed case, punctuation, or non-ASCII characters can therefore order differently across hosts even though the schema currently accepts them.
  - Fix: Use one shared locale-independent code-unit or bytewise comparator over provider and native ID, and cover mixed-case/punctuation IDs in both discovery and preview ordering tests.
  - Requirement: FR1, NFR5

- **The preview validator rejects multiline text emitted by the preview producer** (`src/transcript/coding-session-handoff/types.ts:337`)
  - Issue: The shared `string()` validator rejects every code point below U+0020, including newline and tab, and `parsePreviewEntry` applies it to conversation text at line 535. `previewHandoffCandidates` preserves sanitized message text (including ordinary multiline messages), so a valid produced preview cannot round-trip through its own runtime schema.
  - Fix: Use a preview-text validator that permits the intended whitespace (at least newline, and tab if supported) while still rejecting NUL and unsafe terminal controls, then add a producer-to-`parseSessionPreview` multiline round-trip test.
  - Requirement: FR2; p02-t01, p02-t03
