### Important

- **I1 — Partial Codex cleanup can report `removed` when an attempted call produced no exact ID** (`src/transcript/coding-session-handoff/behavior-gate.ts:1038`)
  - Issue: default Codex cleanup builds commands only from currently known child/parent IDs, but initializes `failed = false` and returns `removed` when that command list is empty or only partially covers attempted creation calls (`src/transcript/coding-session-handoff/behavior-gate.ts:1040-1067`). A parent or successor call can create provider state yet return nonzero, overflow bounded output, or produce an unparseable/ambiguous ID; the gate correctly becomes inconclusive, but its finalized receipt can still falsely claim `providerState: removed`. The partial-failure tests inject a cleanup implementation that always reports removal, so they do not exercise this default edge (`tests/coding-session-handoff/behavior-gate.test.ts:520`).
  - Impact: Disposable Codex state may remain after a failed gate while the audit receipt says it was removed. Activation stays blocked by the inconclusive status, but cleanup truthfulness and operator recovery are broken at a P0 lifecycle boundary.
  - Fix: Track which provider creation/successor calls were attempted and whether every potentially created Codex session has an exact cleanup ID. Delete all known IDs, but return `failed` whenever any attempted creation boundary lacks a provably complete exact-ID set. Add default-cleanup tests for unknown parent, known parent/unknown child, and known parent/child cases.
  - Requirement: FR6, NFR3

  - Fix: Reuse the validated canonical roots retained in the rebuilt plan for execution corroboration, and independently validate/canonicalize reconcile inputs before inspection. Add relative/symlink alias service tests.
