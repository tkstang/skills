### Medium

- **Codex guidance discovery remains unavailable on ordinary multi-thousand-session stores; the 512 MiB cap is now a ~2,048-file ceiling that the public limitations do not state**
  (`src/transcript/session-observer/lib/locate.ts:980`,
  `src/transcript/coding-session-handoff/guidance-discovery.ts:28`,
  `documentation/docs/user-guide/skills/coding-session-handoff.md:85`,
  `skills/coding-session-handoff/SKILL.md:37`)
  - Issue: `prev1-t13` correctly charges Codex exact-all discovery by bounded bytes
    (`min(stat.size, 256 KiB)`), and the intervening lifecycle review marked the prior
    gate M1 resolved on a two-file fixture. On this machine's real store (2,531 Codex
    session files, 7.2 GB) the shipped `discover --provider codex --json` and
    `--provider all --json` still return `discovery-incomplete`, provider `codex`,
    reason `DISCOVERY_BYTE_BUDGET_EXCEEDED`: 2,531 × 256 KiB ≈ 632 MiB exceeds the
    512 MiB aggregate cap, so any Codex store with more than ~2,048 files (a few months
    of ordinary use) is undiscoverable by construction. Codex has no per-cwd directory
    layout, so unlike Claude (which scans only the encoded project directory and works
    here) every session file is charged. The behavior conforms to R2's "aggregate-budget
    failures remain incomplete" allowance and the envelope is truthful and path-free, but
    the user guide "Current limitations" (`:85-96`) and `SKILL.md` do not tell a Codex
    user that the supported workflow cannot work above that store size, and the
    `SKILL.md` step 2 still presents `--provider codex` as an equal first choice.
  - Fix: Either (a) make Codex attribution cheap enough to fit the bound — read a small
    first window (Codex `session_meta` with `cwd` is the first record) to decide cwd
    match and charge only those bytes, performing the full 256 KiB/128-record bounded
    read only for cwd matches; add a fixture with >2,048 small-header Codex files whose
    bounded total exceeds 512 MiB under the current charging but passes under two-stage
    charging — or (b) keep the accounting and state the ceiling plainly in the user
    guide "Current limitations", `SKILL.md` step 2, and the design accepted-revision
    section, so R7's truthful-limitation requirement is met. Do not widen the cap
    silently.
  - Requirement: R2, R7
