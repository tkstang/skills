### Important

- **Store-wide all-or-nothing exact-all discovery makes the guidance product non-functional on realistic transcript stores**
  (`src/transcript/session-observer/lib/locate.ts:486`,
  `src/transcript/session-observer/lib/locate.ts:496`,
  `src/transcript/session-observer/lib/locate.ts:504`,
  `src/transcript/session-observer/lib/locate.ts:738`,
  `src/transcript/coding-session-handoff/guidance-discovery.ts:117`,
  `src/transcript/coding-session-handoff/guidance-cli.ts:217`)
  - Issue: In exact-all mode the shared locator enumerates every transcript in a
    provider store (Claude: every project directory, `locate.ts:738-804`; Codex: every
    dated session file with the recency cutoff disabled, `locate.ts:943`). A single
    transcript whose bounded 128-record/256 KiB prefix is truncated, oversized, or
    lacks a `cwd`/session metadata record throws `DISCOVERY_TRANSCRIPT_INCOMPLETE`
    for the whole provider (`locate.ts:486-507`), even when that transcript is in an
    unrelated project directory and could never be a candidate for the requested
    source. `discoverGuidanceCandidates` then converts any provider throw into a
    `discovery-incomplete` failure for all providers and discards the candidates
    already projected (`guidance-discovery.ts:117-128`), and the CLI emits only a
    generic path-free envelope with no reason code
    (`guidance-cli.ts:217-232`). Independent read-only verification on this machine
    (no provider executed, no store written): `discover --source <this worktree>
    --provider all|claude|codex|cursor --json` all returned
    `discovery-incomplete`. Root causes observed via the shared locator's diagnostic
    hook: Claude — exactly 1 of 168 store-wide transcripts (a tiny file in a different
    project directory) has no `cwd` in its prefix; Codex — one `oversized-record`
    diagnostic among 2,527 session files. The documented workflow
    (`skills/coding-session-handoff/SKILL.md:34-37`) instructs `--provider all` and
    offers no workaround, and the docs page states only that discovery "may require
    explicit selection" (`documentation/docs/user-guide/skills/coding-session-handoff.md:82`).
    The p02-t06/p02-t13 fail-closed contracts were written for the paused automated
    product's batch "all" semantics; for the explicit-selection guidance product they
    convert an unrelated, unattributable transcript into total unavailability, which
    the R2 "incomplete discovery is explicit" allowance did not intend and R7's
    truthfulness requirement does not excuse.
  - Fix: Decide the granularity for the guidance product and align code and
    artifacts together. Preferred: keep enumeration complete and zero-persistence but
    report per-transcript unattributability explicitly instead of aborting — return
    the fully attributed candidate set plus a path-free `unattributable` summary
    (counts by stable reason code such as `oversized-record`,
    `metadata-prefix-incomplete`, `cwd-missing`) in the `discover` envelope, and
    update the `design.md` revision section / R2 wording so "no partial candidate
    set" applies only to the paused executor. Minimum acceptable alternative: (1) in
    `discoverGuidanceCandidates`, isolate failures per provider so `--provider all`
    returns completed providers plus an explicit `incomplete: [{provider, reason}]`
    list rather than discarding everything; (2) surface the stable locator reason
    code in the CLI failure envelope; (3) document in `SKILL.md`,
    `references/provider-guidance.md`, and the docs page that discovery is
    store-wide all-or-nothing per provider and how to narrow with `--provider`.
    Either path must preserve "never select by recency", zero persistence, path-free
    diagnostics, and the paused-executor boundary. Add a regression with a real
    fixture store containing one unrelated cwd-less transcript and one oversized
    record, asserting the source's Codex/Claude candidates are still returned (or the
    per-provider incomplete list is explicit).
  - Requirement: R1, R2, R7

### Medium

- **Cursor guidance discovery is unreachable, but the skill and docs advertise Cursor session discovery**
  (`src/transcript/coding-session-handoff/guidance-discovery.ts:130`,
  `src/transcript/session-observer/lib/locate.ts:1234`,
  `src/transcript/session-observer/lib/locate.ts:1299`,
  `src/transcript/session-observer/lib/locate.ts:1424`,
  `skills/coding-session-handoff/SKILL.md:3`)
  - Issue: The public projection requires `cwdEvidenceQuality === 'independent-exact'`
    for every Cursor transcript, but the shared locator only ever assigns
    `caller-derived-lossy` or `diagnostic` (`locate.ts:1234`, `:1299`, `:1424-1425`);
    no code path produces `independent-exact`. Any Cursor transcript matching the
    source's slug therefore aborts discovery, and a Cursor candidate can never be
    listed, previewed, or prepared. This is the accepted prev1-t06 fail-closed
    disposition, but the skill description ("find a Codex, Claude Code, or Cursor
    conversation"), the docs page (which describes what happens to "an ambiguous
    Cursor candidate", line 71-75), and `references/provider-guidance.md` all imply
    Cursor sessions are discoverable, and none states that Cursor discovery currently
    always reports incomplete. R7 requires the new workflow's evidence to be stated
    honestly per capability.
  - Fix: Either add the independent exact cwd source that the projection is waiting
    for, or state plainly in `SKILL.md`, `references/provider-guidance.md`, and
    `documentation/docs/user-guide/skills/coding-session-handoff.md` that Cursor
    transcripts are not currently discoverable through this skill (discovery reports
    incomplete pending independent source-worktree evidence), and remove/qualify the
    "ambiguous Cursor candidate" prose that describes an unreachable state. Pair the
    doc change with a test asserting the documented per-provider status matrix.
  - Requirement: R2, R7

- **Interactive cwd guard terminates the user's destination shell on mismatch**
  (`src/transcript/coding-session-handoff/guidance.ts:107`,
  `tests/coding-session-handoff/guidance.test.ts:133`)
  - Issue: The rendered command is
    `test "$(pwd -P)" = DEST || { printf ... >&2; exit 64; }; exec PROVIDER ...`. The
    skill tells the user to paste and run this in the destination tab's interactive
    shell. On a cwd mismatch, top-level `exit 64` exits the interactive shell, which in
    an ADE tab closes the tab, so the refusal message is lost with the shell. The only
    coverage runs the command through non-interactive `sh -c` and asserts exit code
    64, which does not exercise the interactive consequence. R4 asks for a guard that
    refuses to launch; killing the shell is a harsher side effect than refusing.
  - Fix: Render the guard without a top-level `exit`, e.g.
    `if test "$(pwd -P)" = DEST; then exec PROVIDER ...; else printf '%s\n' 'Refusing: open the canonical destination worktree first.' >&2; fi`.
    Update the shell test to assert that the mock provider is not invoked from the
    wrong cwd and that the message reaches stderr, rather than asserting a process
    exit code; keep the existing `exec` semantics for the matching-cwd branch.
  - Requirement: R4
