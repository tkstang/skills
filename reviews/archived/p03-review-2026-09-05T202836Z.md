### Important

- **I1 — Production execution treats an unvalidated provider child ID as native success** (`src/transcript/coding-session-handoff/handoff.ts:366`)
  - Issue: `parseObservedChildId` retains any nonempty string from a matching `thread.started.thread_id` or Claude `session_id` and treats one distinct value as an observed identity (`handoff.ts:342-369`). An exit-zero call with that value is then classified `native: succeeded` (`handoff.ts:425-433`). Unlike the behavior gate's exact Codex UUID boundary (`behavior-gate.ts:385-457`), production accepts option-shaped and non-UUID values; the unit fixtures themselves use values such as `observed-codex-child` (`tests/coding-session-handoff/handoff.test.ts:267-316`). This reports an exact machine child identity without validating the P0 untrusted-ID boundary required by FR8 and NFR3.
  - Fix: Centralize provider-specific machine-ID validation and reuse it in both the behavior gate and production parser. Require the exact installed-provider UUID grammar before retaining or corroborating an observed ID; treat a recognized invalid or ambiguous event as no trustworthy ID and classify the operation `indeterminate` unless before-child proof exists. Add Codex and Claude tests for option-shaped, non-UUID, control-bearing, missing, multiple-distinct, and duplicate-identical outputs, and update success fixtures to real valid UUIDs.
  - Requirement: FR8, FR9, NFR3

### Medium

- **M1 — A ready Claude plan cannot round-trip through its own plan parser** (`src/transcript/coding-session-handoff/behavior-contracts.ts:241`)
  - Issue: the required Claude successor argv includes an intentional empty value after `--tools` (`behavior-contracts.ts:229-245`), while `parseNativeInvocation` applies the generic nonempty string parser to every argv entry (`types.ts:1050-1075`). A serialized ready Claude plan therefore fails schema validation even though its producer generated the documented invocation.
  - Fix: Add an argv-specific safe-string parser that permits the intentional empty tool-set value while still rejecting control data, or adopt a verified equivalent no-tools encoding. Add a producer-to-`parseHandoffPlan` Claude ready-plan round-trip test.

- **M2 — Normal planning collapses authentication-required into generic probe failure** (`src/transcript/coding-session-handoff/cli.ts:546`)
  - Issue: `buildDefaultPlan` rewrites every non-authenticated provider result to `probe-failed` and adds only the generic `authentication` missing capability (`cli.ts:535-557`). `capabilityReason` consequently emits `provider-probe-failed` (`handoff.ts:106-123`), discarding the distinct `provider-auth-required` diagnosis and supported login guidance required by the provider design.
  - Fix: Preserve sanitized authentication state through default plan classification and emit the stable `provider-auth-required` reason plus the provider's fixed login command. Test the real default-plan service path for unauthenticated Codex and Claude results, not only injected CLI error rendering.

- **M3 — Execution and read-only reconciliation use caller aliases instead of validated canonical roots** (`src/transcript/coding-session-handoff/cli.ts:737`)
  - Issue: planning validates canonical source/target worktrees, but `defaultExecute` and the default reconcile dependency pass the original caller strings to `corroborateExact` (`cli.ts:703-738`, `cli.ts:751-763`). `exactTranscript` and corroboration then require exact raw-string cwd equality (`cli.ts:606-637`, `cli.ts:667-679`), so an accepted relative or symlink alias can falsely leave a valid child unresolved.
  - Fix: Reuse the canonical source and target worktree roots from the rebuilt validated plan for execution corroboration, and validate/canonicalize reconcile inputs before inspection. Add relative-path and symlink-alias coverage for both execute and reconcile paths.
